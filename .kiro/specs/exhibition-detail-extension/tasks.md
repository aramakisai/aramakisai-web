# Implementation Plan

> 開発サーバーは`make dev` / `make cms-worktree` / `make dev CMS=worktree`経由でのみ起動する (`pnpm dev`・`next dev`・ポート直指定は禁止)。ポート3000と共有CMS (3100) には触らない。
> UIタスクはFigma (fileKey `0kWDqHsLr6xE8b4FFgR1Zx`) の指定ノードをMCP (`get_design_context` / `get_screenshot` / `get_metadata`) で実測してから実装する。実測していない値を独自に埋めない。

- [ ] 1. CMSのスキーマと管理画面の入力
- [ ] 1.1メニューと出店日のフィールドを学生企画に追加し、価格の空値を保存時にnullへそろえる
  - メニューは品名 (必須) と価格の行を並べた順に保持し、説明文「価格が空の行はサイトに表示されません。」を付ける
  - 出店日は開催日を表す文字列の複数値として持ち、入力部品に出店日のチェックボックス部品を指定する
  - 価格は空白を除くと空になる値だけをnullにし、それ以外の文字列は前後の空白も含めて加工しない
  - どちらもカテゴリを問わず表示し、フィールド単位のアクセス制御は付けない (既存のコレクション単位の制御と公開後の編集禁止がそのまま効く)
  - 完了条件: 学生企画のフィールド定義テストで、新フィールドの型・必須・入力部品の指定と、価格の正規化 (`''`・空白のみ→null、`'¥300'`・`' ¥300 '`→そのまま、null・未定義→そのまま) が通る
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 2.1, 2.3, 2.4, 2.5, 3.1, 3.2, 3.4, 6.3_

- [ ] 1.2開催日程の日をチェックボックスで選ぶ出店日の入力部品を作り、importMapに登録する
  - 選択肢は開催日程の各日を暦日順に並べ、ラベルは既存の単一選択と同じ「表示ラベル(M/D)」(ラベル未設定ならM/D)
  - 開催日程に無い日がすでに選ばれていれば「M/D(開催日程外)」でチェック済みのまま並べ、外すと値から消える。解釈できない値と重複は選択肢に含めない
  - チェックの付け外しで、選択中の値を暦日順に並べた配列を保存値にする。開催日程が0件なら「祭基本情報で開催日程を登録してください」と出す
  - `cms/`で`pnpm generate:importmap`を実行し、importMapの差分が新しい部品のimport 1行とマップ1行だけであることを確かめる (Zitadel/S3のエントリが残っていること)
  - 完了条件: 選択肢を作る関数の単体テスト (開催日程順、範囲外の表記、解釈できない値と重複の除外、ラベル未設定時の表記) が通り、importMapに新しい部品が登録されている
  - _Requirements: 2.1, 2.2_

- [ ] 1.3マイグレーションを生成し、CMSとフロントエンドの型を再生成する
  - `cms/`で`pnpm migrate:create student_exhibitions_menu_open_days`を実行し、マイグレーション一覧への登録を確かめる
  - 生成物にメニュー用テーブルと出店日用のtextテーブルの作成以外 (特に`media.prefix`のDROP) が混ざっていれば取り除く。`down`は2テーブルの削除だけ
  - `pnpm generate:types`で`cms/src/payload-types.ts`と`frontend/src/cms-types.ts`を更新する
  - 完了条件: マイグレーションが既存テーブル・列に触れず、生成された型に`menu`と`open_days`が含まれ、`cms/`で`pnpm type-check`と`pnpm test`が通る
  - _Requirements: 6.1, 6.2, 6.5_

- [ ] 2. フロントエンドのデータ取得
- [ ] 2.1 (P) 企画詳細のデータにメニューと出店日を加える
  - メニューは価格がnullでない行だけを、CMSの並び順のまま品名と価格の組で持たせる
  - 出店日は保存値のうち日時として解釈できるものをJST暦日のキーに変換して持たせる
  - どのカテゴリのURLで取得しても同じ値になる (カテゴリ別の企画内容から取らない)
  - 完了条件: 企画詳細の取得テストで、価格nullの行の除外・並び順の保持・出店日キーの変換 (解釈できない値の除外) が確かめられる
  - _Requirements: 3.1, 3.2, 3.5, 4.8, 6.4_
  - _Boundary: getExhibitionDetail_
  - _Depends: 1.3_

- [ ] 2.2 (P) 開催日程の取得と出店日ラベルの組み立てを加える
  - 開催日程を既存のタイムテーブルと同じ規則 (暦日順、表示ラベル未設定なら開催日表記) の日の一覧にし、取得に失敗したら例外にせず「無し」を返す
  - 出店日ラベルは開催日程の順に、選ばれている日のラベルだけを「・」でつなぐ。範囲外の日と重複は出さず、0件なら「無し」
  - 完了条件: 単体テストで、保存順に関係なく開催日程順になること、範囲外・重複の除外、0件と取得失敗で「無し」、ラベル未設定の日の代替表記が確かめられる
  - _Requirements: 4.2, 4.3, 4.4, 4.5, 4.6_
  - _Boundary: getEventDayList, formatOpenDays_
  - _Depends: 1.3_

- [ ] 3. ヘッダー情報列の部品
- [ ] 3.1出店日と出演時間のアイコンを追加する
  - Material Symbolsの`calendar_month`と`schedule`を線画のアイコンとして追加し、フォントのサブセット一覧にもアルファベット順で加える
  - 完了条件: アイコンのテストで2つのアイコンがリガチャ名で描画され、サブセット一覧に2つの名前が含まれる
  - _Requirements: 4.1, 5.2_

- [ ] 3.2 (P) メニュー欄を作る
  - Figma: 出店の例PC `802:731`のメニュー`802:759`をMCPで実測してから実装する (小見出し「メニュー」は12px Regular、表の幅・行間・価格の右寄せを実測値に合わせる)
  - 小見出し「メニュー」と品名・価格の2列の表を出し、価格は入力された文字列のまま表示する。列見出し行は付けない
  - 行が0件ならメニュー欄全体を出さない
  - 完了条件: 部品のテストで、0件のとき何も描画されず、行があるときは小見出しと品名・価格の表が並び順どおり描画される
  - _Requirements: 3.3, 3.4, 3.6, 6.4_
  - _Boundary: ExhibitionMenu_

- [ ] 3.3 (P) 出演時間を情報列の行の見た目に作り替える
  - Figma: ステージの例PC `2:468`の出演時間の行`802:695`をMCPで実測してから実装する
  - 場所の行と同じ文字の体裁で、先頭に出演時間のアイコンを置き、各出演枠の「{日のラベル} {開始}〜{終了} {ステージ名}」と「タイムテーブルを見る」リンクを縦に並べる
  - 見出し「出演時間」と区切り線はなくす。0件なら何も出さない
  - 完了条件: 部品のテストで、見出しが無く、各行の文言とタイムテーブルへのリンクが描画され、0件で何も描画されない
  - _Requirements: 5.2, 5.3, 5.5_
  - _Boundary: ExhibitionPerformances_

- [ ] 3.4 (P) 共有ボタンとリンクのアイコン群を1行にまとめる
  - Figma: ステージの例の共有とリンクの行`803:714`、出店の例の`803:739`をMCPで実測してから実装する
  - リンクのアイコン群から「リンク」の小見出しと外側の枠を外し、アイコンの並びだけにする (並び全体に「リンク」の読み上げ名を付ける)
  - 共有ボタンが後ろに並べる要素を受け取り、共有ボタンを先頭に1行で並べる。コピー完了・手動コピーの通知はその行の下に全幅で出す
  - 完了条件: 部品のテストで、共有ボタンの後ろにリンクが同じ行に並び、「リンク」の文字が無く、リンク0件なら共有ボタンだけになり、コピー失敗時の通知が行の外に出る
  - _Requirements: 5.6, 5.7, 5.8_
  - _Boundary: ShareButton, ExhibitionLinks_

- [ ] 4. 企画詳細ページの組み立て
  - Figma: ステージの例PC `2:468` (出演時間の行`802:695`、共有とリンクの行`803:714`)、出店の例PC `802:731` (出店日の行`802:752`、メニュー`802:759`、共有とリンクの行`803:739`)、SP `2:531` (出店日の行`804:700`) をMCPで実測してから実装する
  - 情報列を タグ → 企画名 → 団体名 → 場所 → 出店日または出演時間 → メニュー → 共有とリンク の順に並べる
  - ステージ以外のページでだけ開催日程を取得し、出店日ラベルがあるときだけ場所の行と同じ体裁 (出店日のアイコン+テキスト) の行を場所の直後に出す。開催日程の取得に失敗しても他の内容は出す
  - ステージのページでは出演時間の行を場所の直後に出し、出店日は出さない。紹介の後ろの出演時間セクションを削除する
  - 完了条件: ページのテストで、情報列の並び、ステージで出店日が出ないこと、ステージ以外で出演時間が出ないこと、開催日程の取得失敗時に出店日の行だけが出ないこと、新フィールドが空のときメニュー欄と出店日の行が出ないこと、紹介の後ろに「出演時間」の見出しが無いことが確かめられ、`frontend/`で`pnpm type-check`・`pnpm test`・`pnpm build`が通る
  - _Requirements: 3.6, 4.1, 4.6, 4.7, 4.8, 5.1, 5.2, 5.4, 5.5, 6.4_
  - _Depends: 2.1, 2.2, 3.1, 3.2, 3.3, 3.4_

- [ ] 5. worktree CMSでの結合確認
  - `cms/`で`pnpm db:up`と`pnpm migrate`を実行してから、`make cms-worktree`を`run_in_background`で起動する (ローカルPostgresは共有CMSと同じDBのため、適用するのは本件の追加だけのマイグレーションに限る)
  - `make dev CMS=worktree`を`run_in_background`で起動し、worktreeのCMSを参照するフロントエンドで確認する
  - 管理画面: 出店日のチェックの付け外しが保存・再読込後も保たれる、開催日程外の値が「(開催日程外)」で表示され外せる、価格を入力して消した行が保存後にnullになる、出展者ロールで自分の企画だけ編集できる
  - 企画詳細ページ: 出店の企画で出店日の行とメニュー欄が出る、価格が空の行が出ない、ステージの企画で出演時間が情報列に出て出店日が出ない、共有とリンクが1行に並ぶ。PCとSPの幅で、Figmaの`2:468`・`802:731`・`2:531`と並びを見比べる
  - 起動で出たimportMapのZitadel/S3の差分はコミットしない。`git restore cms/src/app/(payload)/admin/importMap.js`で戻してから`pnpm generate:importmap`をやり直し、差分が新しい部品の分だけであることを確かめる
  - 後片付け: 自分が起動したサーバーを`make dev-stop` / `make dev-stop CMS=worktree`で止め、ローカルDBは`pnpm migrate:down`で本件のマイグレーションを戻す
  - 完了条件: 上記の管理画面と企画詳細ページの確認項目をすべて満たし、importMapの差分が新しい部品の分だけになっている
  - _Requirements: 1.4, 1.5, 2.2, 2.4, 2.5, 3.1, 3.2, 4.1, 4.4, 5.1, 5.6, 6.2_
