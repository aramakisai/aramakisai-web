- [x] 3. スタンプの共通ロジック
- [x] 3.1 検証値の算出と検証
  - 企画idとカテゴリの組からHMAC-SHA256の検証値(パディング無しbase64url、43文字)を算出し、検証する。秘密値は引数で受け取る
  - `stage`を対象カテゴリから除き、`stage`の算出・検証を受け付けない
  - 不正なbase64url・長さ違い・他の組の値は例外を投げず不一致とし、比較はWebCryptoの検証機能で行う。Node専用APIを使わない
  - 完了条件: 同じ組で同じ値、組が違えば異なる値、他の組の値・改変・長さ違いで不一致、`stage`を受け付けないことを単体テストで確認している
  - _Requirements: 1.1, 1.3, 1.4, 1.6, 1.8_
- [x] 3.2 端末内保存の読み書き
  - キー`aramakisai_mypage`に版番号と名前付きリストの形式で保存し、スタンプのリストを持つ。将来のリスト(ブックマーク等)を名前の追加で足せる形にする
  - 組の一意性で重複を防ぎ、追加結果を「追加」「取得済み」「保存不可」で返す。読み込み時に形式を検証し不正な要素を捨てる。例外を外に出さない
  - 完了条件: 追加・重複・壊れたJSONの読み込み・書き込みが失敗する環境での「保存不可」を単体テストで確認している
  - _Requirements: 2.4, 2.5, 2.6, 3.6_
- [x] 3.3 エリア別の取得率の算出
  - 公開中の`stage`以外の組を分母、そのうち保存済みの組を分子としてエリアごとに取得率(切り捨ての整数)を算出し、取得済みの組を新しい順に並べる
  - エリアの並び順を保ち、分母0のエリアは返さず、取得0件のエリアは0%で返す。エリアを持たない組は「その他」に入れ、対象に無い組(非公開・削除・カテゴリ解除)はどこにも入れない
  - 完了条件: 上記の各規則を単体テストで確認している
  - _Requirements: 3.2, 3.5, 3.10_

  - 完了条件: 本番かつ測定ID有りのときだけ積まれることを単体テストで確認している
