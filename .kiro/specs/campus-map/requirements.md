# Requirements Document

## Project Description (Input)

構内マップページを実装する。キャンパス内のブロック・建造物をポリゴンで表示し、そこに紐づく出展物を辿れるようにする。

### 外観

Figma: [ホームページ / 構内マップ](https://www.figma.com/design/0kWDqHsLr6xE8b4FFgR1Zx/%E3%83%9B%E3%83%BC%E3%83%A0%E3%83%9A%E3%83%BC%E3%82%B8?node-id=39-2)
エリア選択時 / 未選択 / 検索結果 の 3 状態を PC (1440) と SP (390) で用意している。

- OpenStreetMap のデータから生成した地図タイルを画面全体に表示する
- ズームの範囲は、引いたときにキャンパス全体が画面に収まり、寄ったときに模擬店の位置を指せる縮尺までとする。タイルを引き伸ばした表示は行わない
- サイト共通ヘッダー / フッターは表示せず、画面右上のメニューボタンに集約する
- 各ブロック・建造物をポリゴンとして描画し、透明度をつけて重ねる
  - 通常は不透明度 55%、選択中は 72% とし枠線を太くする
  - ポリゴン中央にエリア名ラベルを重ね、選択中は primary で塗る
- 出展物リストの表示
  - デスクトップ: 地図の上に左からペインを重ね、その中にタイルを縦 1 列 (企画一覧ページと同一デザイン)
  - スマートフォン: 画面下部のボトムシートにタイルを縦並び。未選択時はシートが中身の高さまで縮む
- 検索・絞り込み
  - デスクトップ: ペイン上部にキーワード検索とカテゴリチップを置く
  - スマートフォン: シートに同居させるとタイルが 1 件も見えないため、地図の上にフローティングさせる。カテゴリチップは 1 行のまま横スクロールする
- 地図の拡大 / 縮小コントロールと出典表記を地図の右下に重ねる

### 機能

- ポリゴンをクリックすると、そのエリアに紐づく出展物リストを表示する
- エリア未選択時はペイン / シートに「エリアを選択してください」を表示する
- 出展物リストの各エントリをクリックすると企画詳細ページへ遷移する
- キーワード検索とカテゴリ絞り込みの結果を、エリア選択時と同じリストとして表示する

### 参照するデータソース

Payload CMS の以下のコレクション:

- Map Areas (`map_areas`): `name` (ラベル) / `geometry` (GeoJSON Polygon) / `sort` (表示順)
- Student Exhibitions (`student_exhibitions`): `area_id` でエリアに紐づく展示・出店。`booth_label` をカードの所在地表示に使う
- Stages (`stages`): `area_id` でエリアに紐づくステージ。企画は `performance_slots` 経由で辿る

エリアに属する企画は、`student_exhibitions.area_id` の直接参照とステージ経由の両方を束ねる
(`frontend/src/lib/exhibitions.ts` の `areaIds` と同じ集約規則を使う)。
協賛 (`sponsors.area_id`) は本 spec では扱わない。

### CMS に追加するフィールド

- `map_areas.color`: マップ表示色。ポリゴンの塗りと枠線に使う。既存デザイントークンのパレット
  (primary / secondary / accent / accent-alt / info / success / warning) から選ぶ select とし、
  任意の色を入力させない。

### フロントエンドの定数として持つもの

- 地図の初期表示中心・ズーム・表示範囲の上限。会場は荒牧キャンパスで固定のため CMS では管理しない。

### 地図タイルの生成方針

OpenStreetMap Foundation の [Tile Usage Policy](https://operations.osmfoundation.org/policies/tiles/) 第 4 節は、
来場者が実際に閲覧している以外のタイルを先回りして取得する行為 (bulk downloading) を禁止している。
ズーム複数階層の事前取得、後の配布を目的としたタイル集合の構築、高ズーム (z≥14) での広域スキャンが
名指しで挙げられており、回数・枚数・取得間隔による例外は設けられていない。
同ポリシーは代替として自前でのタイル生成 (`run your own tiles`) を案内している。

主要なホスト型タイル配信サービス (Thunderforest / Stadia Maps / MapTiler / Geoapify / Carto / Jawg) にも、
事前取得と自サイトからの再配信の双方を許諾するものは存在しない。

したがって本 spec では、OpenStreetMap のデータから会場周辺のタイルを自前でレンダリングして生成する。
生成は GitHub Actions 上で行い、成果物をリポジトリに取り込む。

### 関連 spec

- **本 spec が依存するもの**
  - `exhibition-pages`: 出展物リストのカードデザインと所在地表記の規則を共有し、クリック時の遷移先として詳細ページの URL を必要とする。先に `exhibition-pages` を実装する
- **本 spec に依存するもの**
  - `responsive-navigation`: 下部ナビゲーションの「マップ」導線の遷移先
  - `digital-signage`: サイネージ画面に構内マップを表示する
  - `pwa-offline`: 本 spec が自前配信する地図タイルをオフラインキャッシュの対象にする

企画詳細ページへのマップ埋め込みは本 spec では扱わない。`exhibition-pages` は実装済みであり、
埋め込みを行う場合は別 spec として起票する。

### 未確定事項

- 管理画面でポリゴン座標をどう編集するか (GeoJSON テキストの直接入力か、地図上での作図 UI か)

## Introduction

構内マップページは、荒牧キャンパスの地図を画面全体に表示し、地図上のブロック・建造物をポリゴンとして重ねることで、来場者が「どこで何をやっているか」を位置から辿れるようにする。エリアを選ぶとそのエリアに紐づく出展物が一覧され、そこから企画詳細ページへ遷移できる。キーワード検索とカテゴリ絞り込みも同じリスト領域で行える。

地図タイルは OpenStreetMap のデータから会場周辺の範囲だけを自前でレンダリングして生成し、自サイトから配信する。OpenStreetMap の公式タイルサーバは事前取得を禁じており、また SLA を持たないため、当日のアクセス集中と後続の `pwa-offline` によるオフライン対応のいずれにも使えない。タイル自体の絵柄は OpenStreetMap のデータと配色スタイルが決めるものであり、本 spec が扱うのはタイルに重ねるレイヤー (ポリゴン、エリア名ラベル、リストのペイン / ボトムシート、各種コントロール) の振る舞いである。

## Boundary Context

- **In scope**: 構内マップページの表示と操作、エリアポリゴンの描画と選択、選択エリアの出展物リスト、キーワード検索とカテゴリ絞り込み、`map_areas` への表示色フィールド追加、会場周辺の地図タイルの自前生成と自前配信
- **Out of scope**: 企画詳細ページ本体 (`exhibition-pages` が所有)、企画詳細ページへのマップ埋め込み、タイムテーブル (`timetable-page`)、下部ナビゲーション (`responsive-navigation`)、サイネージ表示 (`digital-signage`)、協賛企業 (`sponsors.area_id`) のリスト表示、管理画面上での GeoJSON 作図 UI、Service Worker によるオフライン動作 (`pwa-offline` が所有)
- **Adjacent expectations**: 出展物タイルのデザイン、所在地の表記規則、企画詳細ページの URL は `exhibition-pages` に従う。`responsive-navigation` と `digital-signage` は本ページのマップ表示を遷移先 / 表示対象として参照する。`pwa-offline` は本 spec が用意する自前配信のタイル資産をキャッシュ対象として再利用する

## Requirements

### Requirement 1: 構内マップの全画面表示

**Objective:** As a 来場者, I want キャンパスの地図を画面いっぱいに見ること, so that 会場全体の位置関係を一目で把握できる

#### Acceptance Criteria

1. When 来場者が構内マップページを開いたとき, the 構内マップページ shall OpenStreetMap 由来の地図タイルを画面全体に表示する
2. The 構内マップページ shall 地図の初期表示中心・初期ズーム・表示範囲の上限・ズームの上限と下限をフロントエンドの定数から読み取る
3. The 構内マップページ shall 事前に用意した会場周辺の地図タイルを自サイトから配信し、実行時に他者が運用するタイル配信サービスを参照しない
4. The 構内マップページ shall サイト共通ヘッダーおよびフッターを表示せず、他ページへの導線を画面右上のメニューボタンに集約する
5. The 構内マップページ shall 出典表記として `© OpenStreetMap contributors` を地図上に常時表示し、ライセンス情報ページへのリンクを備える
6. When 来場者が拡大 / 縮小コントロールを操作したとき, the 構内マップページ shall 地図の縮尺を変更する
7. If 表示範囲の上限を超える移動または縮小が行われた場合, then the 構内マップページ shall 表示範囲を上限内に収める
8. If ズームの上限または下限を超える操作が行われた場合, then the 構内マップページ shall 縮尺を上限と下限の範囲内に収める
9. The 構内マップページ shall ズームの上限を、地図タイルが実際に用意されている最大の縮尺と一致させ、タイルを引き伸ばした表示を行わない
10. The タイル生成手順 shall 地図タイルを OpenStreetMap のデータから自前でレンダリングして生成し、他者が運用するタイル配信サービスから画像を取得しない
11. While 地図の読み込みが完了していないとき, the 構内マップページ shall 読み込み中であることを地図領域に表示する
12. When 来場者が画面右上のメニューボタンを選択したとき, the 構内マップページ shall サイト共通ヘッダーと同じ他ページへの導線を一覧として開く
13. The 構内マップページ shall タイルが用意されていない座標へのタイル要求を発生させない

### Requirement 2: エリアポリゴンの描画と選択

**Objective:** As a 来場者, I want 地図上の区画を選ぶこと, so that その場所で何が行われているかを知ることができる

#### Acceptance Criteria

1. The 構内マップページ shall `map_areas` の `geometry` を半透明のポリゴンとして地図に重ねて描画する
2. The 構内マップページ shall 各ポリゴンの中央に `map_areas.name` をラベルとして重ねて表示する
3. The 構内マップページ shall ポリゴンの描画順を `map_areas.sort` の昇順に従わせ、`sort` が未設定のエリアを末尾に配置する
4. When 来場者がポリゴンまたはエリア名ラベルを選択したとき, the 構内マップページ shall そのエリアを選択状態にする
5. While エリアが選択状態であるとき, the 構内マップページ shall 該当ポリゴンの塗りの不透明度と枠線の太さを未選択のポリゴンより強調し、エリア名ラベルを選択中の表現に切り替える
6. When 来場者が選択中のエリアを再度選択したとき, the 構内マップページ shall 選択を解除して未選択の状態に戻す
7. If `geometry` が GeoJSON Polygon として解釈できない場合, then the 構内マップページ shall そのエリアを描画対象から除外し、残りのエリアの描画を継続する
8. The CMS shall GeoJSON Polygon として解釈できない `geometry` の保存を拒否する

### Requirement 3: 選択エリアの出展物リスト

**Objective:** As a 来場者, I want 選んだエリアの出展物を一覧すること, so that 現地で回る対象を決められる

#### Acceptance Criteria

1. While エリアが選択されておらず、かつキーワード検索とカテゴリ絞り込みのいずれも適用されていないとき, the 構内マップページ shall リスト領域にエリアの選択を促す案内を表示する
2. When 来場者がエリアを選択したとき, the 構内マップページ shall そのエリアに紐づく出展物をリストに表示する
3. The 構内マップページ shall エリアに紐づく出展物として、`student_exhibitions.area_id` が該当エリアを指すものと、`stages.area_id` を経由して該当エリアに属するステージ企画の双方を対象とする
4. The 構内マップページ shall リストの見出しに選択中のエリア名と該当するタイルの枚数を表示する
5. The 構内マップページ shall 出展物のタイルを企画一覧ページと同一のデザインで表示する
6. The 構内マップページ shall 複数のカテゴリを持つ企画を、カテゴリごとに独立したタイルとして表示する
7. The 構内マップページ shall 公開状態にない出展物をリストに含めない
8. If 選択したエリアに該当する出展物が存在しない場合, then the 構内マップページ shall 件数を 0 として、そのエリアに出展物がない旨を表示する
9. If `map_areas` にエリアが 1 件も登録されていない場合, then the 構内マップページ shall 地図の表示を維持したうえで、エリアが未登録である旨をリスト領域に表示する
10. When 来場者がエリアを選択したとき, the 構内マップページ shall サーバーへのデータ再取得を伴わずにリストを更新する

### Requirement 4: 出展物の検索とカテゴリ絞り込み

**Objective:** As a 来場者, I want 企画名や団体名から探すこと, so that 目当ての企画の場所に辿り着ける

#### Acceptance Criteria

1. The 構内マップページ shall キーワード検索欄とカテゴリ絞り込みを表示する
2. The 構内マップページ shall カテゴリの選択肢を `student_exhibitions.categories` の定義 (ステージ / 展示 / 出店 / その他) と一致させる
3. When 来場者がキーワードを入力してから一定時間が経過したとき, the 構内マップページ shall 企画名と団体名のいずれかが一致するタイルをリストに表示する
4. The 構内マップページ shall キーワードの照合において、全角半角と大文字小文字の違いを吸収する
5. When 来場者がカテゴリを選択したとき, the 構内マップページ shall そのカテゴリのタイルのみをリストに残す
6. While キーワード検索・カテゴリ絞り込み・エリア選択のうち複数が適用されているとき, the 構内マップページ shall すべての条件を同時に満たす出展物のタイルのみを表示する
7. If 条件に一致する出展物が存在しない場合, then the 構内マップページ shall 件数を 0 として、条件の変更を促す案内を表示する
8. While キーワード検索またはカテゴリ絞り込みが適用されているとき, the 構内マップページ shall リストの見出しを、適用中の条件と該当するタイルの枚数を表す表記に切り替える
9. When 来場者が絞り込み条件を変更したとき, the 構内マップページ shall サーバーへのデータ再取得を伴わずにリストを更新する

### Requirement 5: 画面幅に応じたリストと検索部の配置

**Objective:** As a 来場者, I want 手元の画面でも地図とリストの両方を扱うこと, so that スマートフォンでも会場で使える

#### Acceptance Criteria

1. While 画面幅がデスクトップ相当であるとき, the 構内マップページ shall リストを地図の上に重ねた左側のペインとして表示し、地図が隠れきらない幅に収める
2. While 画面幅がスマートフォン相当であるとき, the 構内マップページ shall リストを画面下部のボトムシートとして表示する
3. While 画面幅がスマートフォン相当かつエリアが選択されていないとき, the 構内マップページ shall ボトムシートの高さを内容に合わせて縮める
4. While 画面幅がデスクトップ相当であるとき, the 構内マップページ shall キーワード検索欄とカテゴリ絞り込みをペインの上部に配置する
5. While 画面幅がスマートフォン相当であるとき, the 構内マップページ shall キーワード検索欄とカテゴリ絞り込みを地図の上に重ねて配置し、ボトムシートには含めない
6. While 画面幅がスマートフォン相当であるとき, the 構内マップページ shall カテゴリ絞り込みを 1 行に保ち、収まらない分を横スクロールで辿れるようにする
7. The 構内マップページ shall 拡大 / 縮小コントロールと出典表記を、リストのペインおよびボトムシートと重ならない位置に配置する
8. The 構内マップページ shall デスクトップ相当とスマートフォン相当の境界を単一のブレークポイントとして定義し、検索部とリストの双方で同じ値を用いる
9. The 構内マップページ shall 画面幅に応じて非表示となる側の検索部を、支援技術とキーボード操作の対象から除外する

### Requirement 6: マップエリア表示色の CMS 管理

**Objective:** As a 実行委員, I want エリアごとの表示色を管理画面から選ぶこと, so that 地図上でエリアを見分けやすくできる

#### Acceptance Criteria

1. The CMS shall `map_areas` にマップ表示色のフィールドを持つ
2. The CMS shall 表示色の選択肢をデザイントークンのパレット (primary / secondary / accent / accent-alt / info / success / warning) に限定し、任意の色値の入力を受け付けない
3. When 実行委員がエリアの表示色を変更したとき, the 構内マップページ shall 該当ポリゴンの塗りと枠線にその色を反映する
4. If エリアに表示色が設定されていない場合, then the 構内マップページ shall 既定色でそのポリゴンを描画する
5. The CMS shall 表示色フィールドの追加をマイグレーション経由で DB に反映する
6. The 構内マップページ shall パレットのいずれの色が選ばれた場合でもエリア名ラベルが判読できる表現でラベルを描画する

### Requirement 7: 企画詳細ページへの導線

**Objective:** As a 来場者, I want 一覧から企画の詳細を開くこと, so that 内容を確かめてから足を運べる

#### Acceptance Criteria

1. When 来場者がリスト内の出展物タイルを選択したとき, the 構内マップページ shall そのタイルが表す企画とカテゴリの組に対応する企画詳細ページへ遷移する
2. The 構内マップページ shall タイルに表示する所在地の表記を `exhibition-pages` が定める企画カードの規則に従わせる

### Requirement 8: データ取得に失敗したときの振る舞い

**Objective:** As a 来場者, I want 一部の情報が取れないときでも残りを使うこと, so that 会場で完全に手詰まりにならない

#### Acceptance Criteria

1. If `map_areas` の取得に失敗した場合, then the 構内マップページ shall 地図の表示と操作を維持したうえで、エリア情報を取得できない旨を伝える
2. If 出展物の取得に失敗した場合, then the 構内マップページ shall リスト領域にエラーを表示し、地図の表示と操作を継続できる状態に保つ
3. If 地図タイルの読み込みに失敗した場合, then the 構内マップページ shall ポリゴンの選択とリストの表示を継続する
4. If `map_areas` の取得に失敗した場合, then the 構内マップページ shall タイルの所在地表示を省略したうえで出展物リストの表示を継続する

### Requirement 9: URL による状態の共有と復元

**Objective:** As a 来場者, I want 見ている状態をそのまま共有したり戻ったりすること, so that 連れに場所を伝えたり操作をやり直したりできる

#### Acceptance Criteria

1. The 構内マップページ shall 選択中のエリア・キーワード・選択中のカテゴリを URL のクエリに反映する
2. When 来場者が条件を含む URL を直接開いたとき, the 構内マップページ shall その条件を適用した状態で表示する
3. When 来場者がブラウザの戻る操作を行ったとき, the 構内マップページ shall 直前の条件へ戻る
4. The 構内マップページ shall URL のクエリ形式を企画一覧ページと共有し、両ページ間で条件を引き継げるようにする
5. If URL に複数のエリアが指定された場合, then the 構内マップページ shall 最も小さいエリア ID のみを選択中として扱う

### Requirement 10: キーボードと支援技術による操作

**Objective:** As a 来場者, I want マウスやタッチ以外の手段でも使うこと, so that 操作手段にかかわらず会場の情報に辿り着ける

#### Acceptance Criteria

1. The 構内マップページ shall キーボード操作のみでエリアを選択できる手段を備える
2. When リストの内容が更新されたとき, the 構内マップページ shall 更新されたことを支援技術に通知する
3. While メニューが開いているとき, the 構内マップページ shall キーボードのフォーカスをメニュー内に保ち、Esc キーで閉じられる状態を保つ
4. The 構内マップページ shall 地図・検索部・リストの各領域をキーボードで順に辿れるようにする
