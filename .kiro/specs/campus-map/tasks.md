# Implementation Plan

## 1. サイト共通シェルを route group に分離する

- [x] 1.1 route group を作り、既存ページをディレクトリ単位で移す
  - `app/` 配下に `(site)` と `(fullscreen)` の route group を作る
  - トップページ・`[slug]`・`announcements`・`topics`・`exhibitions` の各ディレクトリを、配下の詳細ページとテストを含めて丸ごと `(site)/` へ移す。`announcements/[id]/` / `topics/[id]/` / `exhibitions/[id]/[category]/` を取り残さない
  - `error.tsx` と `error.test.tsx` を `(site)/` へ移す
  - `global-error.tsx` / `not-found.tsx` / `not-found.test.tsx` / `globals.css` / `layout.tsx` は root 直下に残す
  - 観察可能な完了条件: 既存ページの URL が 1 つも変わらず、`pnpm test` と `pnpm build` が通る
  - 他の作業と同時に進めない。この移動が終わってから以降のタスクに着手する
  - _Requirements: 1.4_

- [x] 1.2 レイアウトを分割し、シェルの有無を構造で表す
  - `app/layout.tsx` から `<Header />` / `<Footer />` の描画を切り出し、新設する `(site)/layout.tsx` へ移す。`<html>` / `<body>` / フォント読み込み / `generateMetadata` は root layout に残す
  - `app/layout.test.tsx` から Footer 配線と SNS リンクの検証を除き、`generateMetadata` の検証のみ残す。除いた検証は新設する `(site)/layout.test.tsx` へ移す。移さないと root layout のテストが失敗したまま残る
  - `(site)/not-found.tsx` を新設する。これがないと `(site)` 配下の 404 がヘッダーとフッターを失う
  - `(fullscreen)/layout.tsx` を新設する。余白を持たず、地図が画面いっぱいに広がれるよう高さを明示的に確保する
  - `(fullscreen)/error.tsx` を新設する。これがないと全画面ページのエラーが `global-error.tsx` まで抜け、`<html>` ごと差し替わる
  - 観察可能な完了条件: 既存ページでヘッダーとフッターが従来どおり表示され、存在しない URL でもシェル付きの 404 が出る。`(fullscreen)` 配下にはどちらも表示されない。`pnpm test` と `pnpm build` が通る
  - _Requirements: 1.4_
  - _Depends: 1.1_

## 2. 地図の前提となる定数と検証ユーティリティを用意する

- [x] 2.1 構内マップの表示設定を独立した定数モジュールとして定義する
  - 地図の初期表示中心・初期ズーム・表示範囲の上限・ズームの下限と上限を 1 か所にまとめる
  - ズーム範囲は下限 17・上限 19。タイルが実在する最大の縮尺と上限を一致させ、引き伸ばし表示を許さない設定値を持たせる
  - タイル配信パスのテンプレートと、出典表記の文言を同じモジュールに置く。出典表記は `© OpenStreetMap contributors` の文字列とライセンス情報ページへのリンクを含む形とする
  - デスクトップとスマートフォンの境界となるブレークポイントを 1 つ定義する。Tailwind のブレークポイント名と対応させ、検索部・ペイン・シートのすべてがこの 1 つを参照する
  - **CMS クライアントにも環境変数モジュールにも依存させない。** 環境変数モジュールは読み込み時に検証して失敗すると例外を投げるため、依存させるとビルドパイプライン外のスクリプトから読めなくなる
  - 観察可能な完了条件: 中心・ズーム範囲・表示範囲・タイルパス・出典表記・ブレークポイントが型付きの定数として読み出せ、このモジュールが他のアプリケーションコードを import していない
  - _Requirements: 1.2, 1.5, 1.9, 5.8_
  - _Boundary: campus-map-config_

- [x] 2.2 (P) GeoJSON Polygon のランタイム検証と重心算出を実装する
  - CMS の `json` 型が返す任意の値から GeoJSON Polygon を判定するスキーマを定義する。経度と緯度の範囲、外環の点数、リングの閉包を検証する。座標の第 3 要素 (高度) は仕様上許されるため受け入れて無視する
  - 検証結果を成功と失敗の判別可能ユニオンで返す。失敗時は理由を保持する
  - 座標の型は可変配列として定義する。読み取り専用にすると地図ライブラリが要求する GeoJSON の型へ代入できず、描画時に型アサーションが必要になる
  - エリア名ラベルの配置に使う重心を外環から算出する
  - スキーマ定義を独立して export する。CMS 側の保存時検証が同じ規則を使えるようにする
  - 観察可能な完了条件: 正当な Polygon・座標範囲外・リング未閉包・高度付き座標・配列でない値のそれぞれに対して期待どおりの判定が返るユニットテストが通る
  - _Requirements: 2.1, 2.7_
  - _Boundary: campus-map-geometry_

## 3. 会場周辺の地図タイルを生成して資産にする

- [x] 3.1 タイル生成ワークフローと範囲算出スクリプトを実装する
  - 表示設定の定数から対象範囲とズームごとのタイル座標・枚数を算出するスクリプトを書く
  - 算出した枚数が想定 (z17〜19 合計で約 1323 枚) の 1.5 倍を超える場合、レンダリング前に停止して枚数を提示する
  - OpenStreetMap のデータからレンダリングするワークフローを GitHub Actions に置く。他者が運用するタイル配信サービスから画像を取得してはならない。手順は OSM の extract 取得 → 対象範囲の切り出し → タイルサーバのコンテナへインポート → z17〜19 のレンダリング → artifact 出力
  - 手動実行 (`workflow_dispatch`) とする。通常のデプロイ経路には含めない
  - ロジックはワークフローの YAML ではなくスクリプトに置く
  - 生成後の枚数と総容量を検証するスクリプトを併せて書く
  - 観察可能な完了条件: ワークフローが手動実行でき、範囲算出スクリプトがズームごとの枚数と総枚数を出力する。レンダリングを伴わないドライランで枚数を確認できる
  - _Requirements: 1.10_
  - _Depends: 2.1_
  - _Boundary: generate-map-tiles_

- [ ] 3.2 ワークフローを実行してタイル資産をリポジトリに配置する
  - ワークフローを実行し、artifact を取得する
  - 配信パス配下へ展開する。範囲を狭める変更を行った場合に古いタイルが残らないよう、展開前に既存のタイルを削除する
  - 日本語のラベルが正しく描画されていることを目視で確認する
  - 検証スクリプトで、設定したズーム範囲のすべてのタイルが揃っていることと総容量を確認する
  - 実測した枚数と総容量が想定 (約 1323 枚・約 7.7MB) から大きく外れる場合、design と research の見積もりを実測値へ更新する
  - 観察可能な完了条件: 配信パス配下にズーム 17〜19 のタイルが揃い、検証スクリプトが欠落なしと総容量を報告する
  - _Requirements: 1.1, 1.3_
  - _Depends: 3.1_
  - _Boundary: generate-map-tiles_

  - 選択肢は定数配列から組み立て、既存コレクションと同じ書き方に揃える。トークン名をそのまま値として使う
  - `geometry` に保存時の検証を追加し、GeoJSON Polygon として解釈できない値を拒否する。検証規則はフロントエンドと同じものを使う
  - マイグレーションを生成して登録し、型を再生成してフロントエンド側の型定義まで同期する
  - フィールドの型・選択肢・必須でないことと、検証が不正な値を拒否することを検証するユニットテストを追加する
  - 観察可能な完了条件: 管理画面でエリアに表示色を選べ、不正な GeoJSON の保存が拒否される。`pnpm migrate` の再実行で新マイグレーションが適用され、cms の `pnpm test` が通る。型の再生成結果がコミットに含まれる
  - _Requirements: 2.8, 6.1, 6.2, 6.5_
  - _Depends: 2.2_
  - _Boundary: map-areas collection_

## 5. データ取得層とクエリ解釈を作る

- [x] 5.1 絞り込み条件の解釈と URL 生成を実装する
  - キーワード・カテゴリ・選択中エリアを URL クエリから解釈する。エリアは単一選択として扱う
  - 複数のエリアが指定された場合は**最小のエリア ID** を採用する。既存のクエリ解釈は受け取ったエリア ID を昇順にソートして返すため、その先頭が最小 ID になる。URL 上の出現順の先頭ではない
  - 同じ条件から URL を組み立てる。企画一覧ページと同じ正規化 (カテゴリとエリア ID の昇順ソート、カンマ区切り) を行う
  - 既存の URL 生成処理はパスを固定で持つため直接は流用できない。パスを引数に取る関数を既存モジュールに新設し、既存の公開関数をその薄いラッパーに置き換える。既存関数のシグネチャは変えない
  - 観察可能な完了条件: 複数のエリア値を含むクエリから最小の ID が選択中エリアとして解釈され、同じ条件を URL に戻すと企画一覧と同じ正規化された形になるユニットテストが通る
  - _Requirements: 9.1, 9.4, 9.5_
  - _Boundary: campus-map lib, exhibitions lib_

- [x] 5.2 構内マップ用のデータ取得と集約を実装する
  - 既存モジュールの結合コンテキスト構築処理とカード組み立て処理に `export` を追加する。既存の公開関数のシグネチャは変更しない
  - エリア一覧と結合済みの出展物カードを取得する。取得は 4 本の並列呼び出しとする
  - **エリアの取得は 1 回のみ**とし、その結果をポリゴン描画と所在地解決の双方に渡す。既存の並列取得処理はエリアを内包しており、そのまま使うと二重取得になるうえ、エリアと出展物の失敗を独立して扱えなくなるため使わない
  - 出展物本体は公開状態のものだけを企画 ID 昇順で取得する。この取得条件は企画一覧ページと揃える。カードの並び順の前提になる
  - エリアの取得失敗と出展物の取得失敗を独立した結果として表現し、片方の失敗がもう片方を巻き込まないようにする
  - エリアの取得に失敗した場合、結合コンテキストには空のエリア配列を渡す。所在地が解決できずカードの所在地表示が省略されるが、リスト自体は表示できる
  - 検証に失敗したエリアを描画対象から除外し、残りのエリアを返す
  - エリアの表示順は CMS の表示順の昇順とし、表示順が未設定のエリアは末尾に置く。未設定を取りうることを型に反映する
  - エリアに属する出展物として、エリアを直接指す企画と出演ステージ経由で属する企画の双方を対象とする
  - 表示色が未設定または未知の値のエリアを既定色に解決する。色値はデザイントークンの定義から導出し、二重に持たない
  - 絞り込みは行わない。取得したカードを全件返す
  - 観察可能な完了条件: エリア取得が失敗し出展物取得が成功したときに、エリア側がエラー・出展物側が読み込み済みで返り、カードの所在地が空になる統合テストが通る。表示順が未設定のエリアが末尾に並ぶことも確認できる
  - _Requirements: 2.3, 2.7, 3.2, 3.3, 3.6, 6.4, 7.2, 8.1, 8.2, 8.4_
  - _Depends: 2.2, 5.1_
  - _Boundary: campus-map lib_

- [x] 5.3 非公開の出展物がリストに現れないことを検証する
  - 公開状態にない出展物が取得結果に含まれないことを確認する。除外は CMS のアクセス制御で成立しているため、フロントエンドの追加実装は伴わない
  - 観察可能な完了条件: 非公開レコードを含むデータに対して公開分のみが返る統合テストが通る
  - _Requirements: 3.7_
  - _Depends: 5.2_
  - _Boundary: campus-map lib_

## 7. 地図の描画と操作を実装する

- [x] 7.1 地図ライブラリを導入し全画面の地図を描画する
  - 地図ライブラリとその React ラッパーを依存に追加する。**型定義パッケージを開発依存に追加する**。これがないと型チェックが通らない
  - **地図ライブラリの CSS を読み込む**。読み込まないとタイルの配置とコントロールの位置が崩れる。型チェックでは検出されない
  - **地図コンテナに明示的な高さを与える**。高さが決まらないとコンテナの高さが 0 になり地図が表示されない
  - 自前配信のタイルを画面全体に表示する。表示設定の定数から中心・ズーム範囲・表示範囲の上限を読み取り、コンポーネント内に値を持たない
  - 表示範囲の上限を超える移動と、ズームの上限・下限を超える操作を範囲内に収める。表示範囲の制限は既定では境界外へのドラッグを許すため、粘性の設定を最大にして境界外へ出られないようにする
  - **タイルレイヤーに読み込み範囲を指定し、タイルが用意されていない座標への要求そのものを発生させない**。表示範囲の制限はビューの制限であってタイル要求の制限ではない。範囲外の要求は静的アセットとして解決されず、配信基盤の課金対象になる
  - ズームの上限をタイルが実在する最大の縮尺と揃える。上限より上のズームは存在しないため、引き伸ばし表示を別途禁止する設定は不要
  - 読み込みに失敗したタイルの代替画像を指定し、破損画像として表示されないようにする
  - 出典表記を地図上に常時表示する
  - エリアの選択は URL を書き換えず、コールバックで親へ通知する形にする
  - 観察可能な完了条件: 構内マップのパスを開くと自前タイルの地図が画面全体に表示され、ズームと移動が定められた範囲に収まる。地図を端までドラッグしても範囲外のタイル要求が発生しない。`pnpm type-check` と `pnpm build` が通る
  - _Requirements: 1.1, 1.2, 1.3, 1.5, 1.7, 1.8, 1.9, 1.13, 8.3_
  - _Depends: 2.1, 3.2, 6_
  - _Boundary: CampusMapView_

- [x] 7.2 エリアポリゴンとエリア名ラベルを地図に重ねる
  - 検証済みのエリアを半透明のポリゴンとして描画する。表示順は取得層が決めた順に従う
  - 塗りの不透明度は通常 55%、選択中 72% とし、選択中は枠線を太くする
  - エリアごとの表示色を塗りと枠線に反映する
  - ポリゴンの中央にエリア名のラベルを重ねる。選択中はラベルを選択中の表現に切り替える
  - **ラベルに背景または縁取りを与え、7 色のいずれの塗り色や地図の絵柄に重なっても判読できるようにする**。7 色すべてに対するコントラストをユニットテストで検証する
  - 選択状態の反映は変更可能なスタイルの props で行う。図形データの props は変更しても描画に反映されない
  - クリックの購読はイベントハンドラの props で行う
  - ポリゴンをキーボードでフォーカスでき、Enter または Space で選択できるようにする
  - 観察可能な完了条件: 複数のエリアが色分けされたポリゴンとして地図上に並び、選択中の 1 つだけが強調される。どの色でもエリア名が読める。キーボードだけでエリアを選べる
  - _Requirements: 2.1, 2.2, 2.3, 2.5, 6.3, 6.6, 10.1_
  - _Depends: 5.2, 7.1_
  - _Boundary: AreaPolygonLayer, AreaLabelMarker_

- [x] 7.3 ポリゴンの選択と解除を親へ通知する
  - ポリゴンまたはエリア名ラベルを選ぶと、そのエリアの識別子をコールバックで通知する
  - 選択中のエリアを再度選ぶと選択解除として通知する
  - 地図コンポーネント自身は URL を書き換えない
  - 観察可能な完了条件: ポリゴンをタップするとコールバックが選択中の識別子で呼ばれ、もう一度タップすると解除として呼ばれるテストが通る
  - _Requirements: 2.4, 2.6_
  - _Depends: 7.2_
  - _Boundary: CampusMapView, AreaPolygonLayer_

- [x] 7.4 拡大縮小コントロールとメニューボタンを配置する
  - 地図の拡大縮小コントロールを地図上に重ねる。操作でズームが変わる
  - サイト共通ヘッダーの代わりとなるメニューボタンを画面右上に置く
  - メニューを開くと、サイト共通ヘッダーと同じ遷移先の一覧を表示する。掲載項目はヘッダーの定義を参照し、二重に列挙しない。定義が取り出せない形になっている場合は共有可能な定数へ切り出す
  - メニューを開いている間はキーボードのフォーカスをメニュー内に保ち、Esc キーで閉じてトリガーへフォーカスを戻す。開いている間は地図へのポインタ操作を遮る
  - 観察可能な完了条件: 拡大縮小の操作でズームが変わる。メニューからサイトの各ページへ遷移でき、開いている間は Tab がメニュー外へ出ず Esc で閉じる
  - _Requirements: 1.4, 1.6, 1.12, 10.3_
  - _Depends: 7.1_
  - _Boundary: MapZoomControl, MapMenuButton, CampusMapView_

## 8. リストと検索部を実装する

- [x] 8.1 絞り込み状態と URL 同期のフックを実装する
  - キーワード・カテゴリ・選択中エリアを 1 つの状態として保持する
  - **状態の変更を URL へ反映する際にページ遷移を発生させない**。ルーターの遷移 API を使うとサーバー側の再レンダリングが走り、CMS への再取得が発生する。履歴 API を直接使う
  - エリアの選択・解除とカテゴリの変更は履歴に積む。キーワードはデバウンス後の確定値を 1 エントリとして積む。1 文字ごとに積まない
  - ブラウザの戻る操作を購読し、URL 側の変化を状態へ反映する
  - キーワードの入力は状態へ即時反映し、URL への反映と絞り込みの適用のみを遅らせる。デバウンス時間は企画一覧ページの絞り込み UI と揃える

  - 絞り込み適用の状態は、エリア・キーワード・カテゴリの任意の組み合わせを 1 つの状態で表す。エリアのみと検索結果を別の状態にしない。別にすると、エリア未選択でキーワードだけが入った場合にどちらを表示するか決まらなくなる
