# Implementation Plan

- [ ] 1. 依存する公開面と純粋ロジックを整える

- [x] 1.1 構内マップのエリア取得と変換を企画詳細ページから使えるようにする
  - 区画データの変換関数を公開面へ出し、形状検証に失敗した区画を除外する既存の挙動を変えない
  - エリアのみを取得する経路を設け、出展物・ステージ・上演枠の取得を伴わないようにする
  - 既存の一括取得は区画データの生の応答をエリア変換と出展物の結合の双方に使い回しているため、取得と変換を別々の内部ヘルパーに分け、双方がそれらを組み合わせる形にする
  - 区画データの取得が従来どおり一度しか走らないことを既存テストで確認する
  - 取得の成否は既存のエリア取得と同じ成功・失敗の形で表す
  - 構内マップページの表示と挙動が従来どおりであることを既存テストで確認する
  - 新しい取得経路がエリアのみを要求し、取得失敗時に失敗として返ることをテストで確認する
  - _Requirements: 4.2_
  - _Boundary: campus-map lib_

- [ ] 1.2 (P) 塗りつぶし形状の位置アイコンを追加する
  - Material Symbols Sharp の位置アイコンのうち塗りつぶし形状のものを、既存のアイコン定義と同じ方式で一件追加する
  - 形状データは公式の配布元から取得したものを用い、記憶による書き起こしを行わない
  - 既存のアイコン生成の仕組みと既存アイコンには手を加えない
  - 追加したアイコンが描画され、色が呼び出し側の指定に従うことをテストで確認する
  - _Requirements: 1.6_
  - _Boundary: icons_

- [x] 1.3 (P) 対象エリアの解決と表示範囲の算出を実装する
  - 企画が持つエリア ID の並びと取得済みの区画から、描画できる対象エリアを並び順を保って抽出する
  - 一致する区画が一件もない場合は対象エリアなしとして返す
  - 抽出した先頭を遷移先の決定に用いるエリアとして併せて返す
  - すべての対象エリアの頂点を含む矩形範囲を求める
  - 指定したエリアを選択状態とする構内マップページの遷移先を組み立てる
  - 区画の座標は経度・緯度の順で保持されているため、緯度・経度の順を取る矩形範囲へ詰め替える
  - 地図ライブラリにも React にも依存しない純粋な関数として実装する
  - 並び順の保持・対象なしの判定・矩形範囲・遷移先のそれぞれをテストで確認する
  - _Requirements: 1.2, 1.11, 3.2, 3.3, 4.1, 4.3_
  - _Boundary: location-map lib_

- [ ] 2. 地図の構成要素を実装する

- [x] 2.1 (P) 対象エリアを指すマップピンを実装する
  - 区画の重心にピンを配置し、地図の描画内容に重なった状態でも判別できる寸法で表示する
  - 構内マップのエリア名ラベルと同じ仕組みでマーカーを組み立て、新しい描画方式を持ち込まない
  - ピンはクリックを受け取らず、操作は下層のポリゴンへ素通りさせる
  - 色は既存のカラートークンで与え、生の色値を書かない
  - 対象エリアが複数あるとき、そのすべてにピンが描画されることをテストで確認する
  - _Requirements: 1.4, 1.5, 1.6, 1.7_
  - _Boundary: AreaPin_
  - _Depends: 1.2_

- [x] 2.2 (P) 初期表示位置へ戻す操作を実装する
  - 地図を初期表示と同じ範囲へ戻す操作を提供する
  - 拡大縮小の増減操作は設けない
  - キーボード操作で到達および実行できるようにする
  - Figma の PC と SP の定義に従った配置と見た目にする
  - 地図を移動させたのち操作すると初期表示範囲へ戻ることをテストで確認する
  - _Requirements: 2.4_
  - _Boundary: RecenterButton_

- [ ] 2.3 埋め込み用の地図コンテナを実装する
  - セクション内の有限高で地図を構成し、ビューポート高に依存させない
  - 縮尺範囲と表示範囲の上限は構内マップと同じ設定値をそのまま適用する
  - 初期表示は対象エリアがすべて収まる位置と縮尺で行う。中心と縮尺を個別に与えると範囲指定が無効になるため、範囲のみを与える
  - 縮尺範囲の下限でも対象エリアが収まらない場合は、下限を適用した上で対象エリア全体の中心を表示領域の中央に置く
  - 対象エリアはすべて同一の描画規則で描き、いずれかを選択状態として区別しない
  - ポリゴンのクリックに副作用を持たせず、地図の移動と拡大縮小を遷移の契機としない
  - 来場者による拡大縮小と移動を受け付け、操作後も対象エリアの描画とピンが維持されることをテストで確認する
  - _Requirements: 1.9, 1.10, 1.11, 1.12, 2.1, 2.2, 2.3, 3.4_
  - _Depends: 2.1, 2.2_

- [x] 2.4 (P) 地図描画資産の読み込み失敗を捕捉する境界を実装する
  - 地図本体の読み込みと初期描画の失敗を捕捉し、指定されたフォールバックへ切り替える
  - 捕捉した失敗をページ全体のエラーへ再送出しない
  - 現行の React では error boundary はクラスコンポーネントでのみ実装でき、本リポジトリに前例がないため新規のパターンとなる
  - 失敗を注入したときにフォールバックが描画され、境界の外へ例外が漏れないことをテストで確認する
  - _Requirements: 5.2_
  - _Boundary: MapErrorBoundary_

- [ ] 3. 企画詳細ページへ組み込む

- [ ] 3.1 地図の遅延読み込みとフォールバックを担う宿主を実装する
  - 地図本体をクライアント側で遅延読み込みし、ページの初期表示を待たせない
  - 読み込み中はセクションの占有領域を確保し、レイアウトのずれを生じさせない
  - 読み込みに失敗した場合はエリア名と構内マップページへの遷移リンクへ切り替える
  - 読み込み中の表示と読み込み失敗時の表示がそれぞれ描画されることをテストで確認する
  - _Depends: 2.3, 2.4_
  - _Requirements: 5.1, 5.2, 5.4_

- [ ] 3.2 企画位置セクションを実装する
  - 区画データは呼び出し元から受け取り、自身では取得しない。取得を内包すると企画詳細の取得と直列になるため
  - 受け取った区画と企画のエリア ID から対象エリアを解決し、解決できない場合は自身を描画しない
  - 区画データが得られなかった場合も自身を描画せず、ページ全体のエラーへ昇格させない
  - キャプションには企画詳細ページの所在地表記をそのまま用いる。ブース情報は表示モデルへ個別に写像されておらず所在地表記へ結合済みである。所在地表記が得られない場合は対象エリア名を用いる
  - 構内マップページへの遷移リンクを置き、遷移先が判別できる文言とキーボード操作での到達を確保する
  - Figma の PC と SP の定義に従った寸法と配置で表示し、表示幅に応じて地図領域の寸法を変える
  - 既存のカラートークンとタイポグラフィの定義のみを用いる
  - 対象エリアの有無・区画取得の成否それぞれでセクションの描画可否が切り替わることをテストで確認する
  - _Depends: 1.3, 3.1_
  - _Requirements: 1.3, 1.8, 3.1, 3.5, 4.1, 4.4, 6.1, 6.2, 6.3, 6.4, 6.5_

- [ ] 3.3 企画詳細ページの末尾にセクションを配置する
  - 既存のセクション群の末尾に企画位置セクションを置き、他のセクションの構造を変えない
  - 紹介セクションは紹介文がある場合にのみ描画されるため、その有無にかかわらず末尾へ置く
  - 区画データの取得と企画詳細の取得をページ自身が並行して起動し、取得済みの区画をセクションへ渡す
  - 区画データの取得に失敗した場合は空の区画としてセクションへ渡し、ページ全体のエラーへ昇格させない
  - セクションの描画可否にかかわらず、ギャラリー・基本情報・リンク・紹介が従来どおり描画されることをテストで確認する
  - _Depends: 1.1, 3.2_
  - _Requirements: 1.1, 4.2, 4.5, 5.3_

- [ ] 4. 検証

- [x] 4.1 エリア ID の並び順に対する回帰テストを設ける
  - 直接の所在エリアと出演ステージの所在エリアの双方を持つ企画で、並びの先頭が直接の所在エリアとなることを固定する
  - 直接の所在エリアを持たずステージ経由でのみ解決する企画で、先頭が最初の出演ステージの所在エリアとなることを固定する
  - 企画の表示モデルを組み立てる既存処理の並び順が変わった場合に、このテストが失敗することを確認する
  - _Requirements: 3.3_

- [ ] 4.2 表示可否の分岐を統合テストで確認する
  - 所在エリアを持つ企画でセクションが描画され、キャプションに企画詳細ページの所在地表記が含まれること
  - 所在エリアを持たずステージ経由でエリアを解決する企画でもセクションが描画されること
  - 対象エリアを持たない企画でセクションが描画されず、他のセクションが従来どおり描画されること
  - 区画データの取得に失敗した場合にセクションが描画されず、既存の所在地テキスト表記が維持されること
  - 形状検証に失敗する区画が混在する場合に、当該エリアのみが対象から除外されること
  - 上記すべてが通ることを確認する
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 4.5_

- [ ]* 4.3 主要な操作経路を E2E で確認する
  - 企画詳細ページから遷移リンクを辿り、構内マップページで当該エリアが選択状態となること (要件 3.2)
  - 地図を移動したのち初期表示位置へ戻す操作で復帰すること (要件 2.4)
  - 遷移リンクがキーボード操作で到達および実行できること (要件 6.4)
  - いずれも 4.2 の統合テストで機能自体は担保済みであり、実ブラウザでの経路確認として後追いできる
  - _Requirements: 2.4, 3.2, 6.4_
