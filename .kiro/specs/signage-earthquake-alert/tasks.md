# Implementation Plan

2つのリポジトリとInfisicalにまたがる。各タスクの題名の先頭に、作業する場所(`aramakisai-web`・`aramakisai-infra`・`Infisical`)を書く。PRはdevへ出し、devからmainへ上げる。

**期限と順序**: リレーは稼働期間(2026-10-23 9:00〜2026-11-22 0:00、日本時間、終端を含まない)の開始時刻に、Cronとalarmで自動的に上流へ接続する。開始時刻の前日(2026-10-22)までに、次の順で本番への反映を終える(タスク10)。

1. Infisical prodのキー(タスク1)
2. CMSのmainへのマージと、ArgoCDによるマイグレーションの反映(緊急地震速報のグループができる)
3. `aramakisai-infra`のCMSのenv・ExternalSecretの反映と、Podのenvの実測(タスク8)
4. frontendのmainへのマージ(サイト・リレーのデプロイ。リレーは稼働期間の前なので接続しない)

frontendはグループが無くても既定の文言で動き、CMSのパネルはリレーに届かなければその旨を出すだけなので、順序が崩れても壊れない。ただし上の順で出すと、各段の反映をCMSの管理画面で確かめながら進められる。稼働期間に入った後(2026-10-23 9:00以降)は、リレーのパス(`frontend/workers/signage-quake/`・`frontend/src/lib/signage-quake.ts`・`frontend/src/lib/signage-channel.ts`)を変えるPRをmainへマージしない(デプロイのたびに上流が最大30秒切れるため)。

**開発サーバー**: `make dev`・`make signage-dev`・`make quake-dev`(タスク4.1で追加)・`make cms-worktree`経由でだけ起動し、`pnpm dev`・`next dev`・`wrangler dev`を直接実行しない。ポートは自分で選ばない。Claudeが起動するときは`run_in_background`を使い、他のセッションや人間が立てたサーバーを止めない。ポート3000には触らない。CMSのスキーマを変えるため、CMSを伴う検証は`make cms-worktree`と`make dev CMS=worktree`(または`make signage-dev CMS=worktree`)で行い、共有の`make cms`は使わない。

**UIの実装と確認**: オーバーレイ(固定の帯・段階のスライドの枠・注記)は、Figmaファイル`0kWDqHsLr6xE8b4FFgR1Zx`(ページ「デジタルサイネージ」`828:2`)の指定したnode-idをFigma MCPで実測してから実装する。UIの確認は実ブラウザで寸法を測って行い、vitestの通過だけで完了扱いにしない。端末とCMS管理画面の見た目を変えるコード(タスク5.4・6)のコミットは、タスク9の実ブラウザでの確認の後に行う。実ブラウザでの確認の後は必ずブラウザを閉じ、判断に使ったスクリーンショットのフルパスを記録する。
