# Implementation Plan

## 全タスク共通の制約

- 開発サーバーは`make dev`でだけ起動する(Claudeは`run_in_background`で実行する)。`pnpm dev`・`next dev`・`-p`/`--port`で直接起動するのは禁止。ポート3000には触らない
- Playwright(MCPのブラウザを含む)を使ったら、最後に必ず`browser_close`する
- コミットは、ユーザーが実ブラウザで確認した後に行う

- [x] 1. 基盤: 色トークン・アイコン・トーストの拡張
- [x] 1.1 現在地の色トークンとアイコンの字形を使えるようにする
  - テーマの色に`location`(#1a73e8)と`location-accuracy`(#1a73e826)を足す。JSから値を読むときは既存の構内マップと同じくテーマ設定を読み込む流儀に従い、hexを二重に持たない
  - Material Symbolsの読み込み対象のアイコン名に`my_location`を加える
  - 完了状態: `bg-location`のクラスがビルドで生成され、`my_location`がページ上で字形として描かれる。型チェックが通る
  - _Requirements: 1.3, 3.2_

- [x] 1.2 (P) 既存のトーストで文言とリンクの有無を上書きできるようにする
  - 任意の文言を渡すとkindの既定文言の代わりに出し、リンク表示をオフにすると「マイページ」リンクを描かない
  - 指定しないときは従来どおりの文言とリンクで、スタンプ機能の呼び出し側は変更しない。`role="status"`・位置・表示時間・重なり順は変えない
  - 完了状態: 文言の上書き、リンク非表示、既定時の従来どおりの文言とリンク、`role="status"`を確かめる単体テストが通る
  - _Requirements: 4.6, 4.7, 4.8_
  - _Boundary: StampToast_

- [x] 2. 位置の監視と構内の範囲判定
- [x] 2.1 (P) 位置の監視を開始・停止し、構内の範囲内の位置だけを返すフックを作る
  - マウントしただけでは位置情報APIに触れず、開始の操作で初めて高精度・タイムアウト15秒・キャッシュ無しの継続取得を始める。取得中にもう一度開始しても監視を重ねない
  - 位置を受け取るたびに構内の範囲(`campusBounds`の南西・北東を含む閉区間)で判定し、範囲内なら位置と精度を更新する。監視を始めて最初の範囲内の位置でだけ初回の通知を1回呼ぶ
  - 範囲外の位置・エラー(種類を区別しない)・閲覧環境の非対応のいずれでも、監視を止めて未取得の状態に戻し、失敗回数を1増やす
  - 監視ごとにセッションを区別し、停止後に古いセッションから届いたコールバックは捨てる。アンマウント時に監視を止める
  - 位置はコンポーネントの状態にだけ持ち、送信・保存・計測イベント送信をしない
  - 完了状態: 位置情報APIをモックした単体テストで、マウント時に取得しない・開始と更新・初回通知が1回だけ・範囲外とエラー1〜3と非対応での停止と失敗回数の増加・取得中の開始で再登録しない・アンマウントでの停止・古いセッションの無視、範囲判定の内側・境界上・外側が通る
  - _Requirements: 2.1, 2.2, 2.3, 2.6, 2.7, 3.1, 4.1, 4.2, 4.3, 4.4, 4.5_
  - _Boundary: useUserLocation_

- [x] 3. 地図上の現在地ボタン・マーカー・失敗トースト
- [x] 3.1 現在地ボタンをズームコントロールと同じ右下の角に置く
  - Leafletの右下のコントロールとして容器を作り、その中にReactでボタンを描く。容器ではドラッグとスクロールの伝播を止め、クリックはボタンに届くようにする。アンマウント時に容器を取り除く
  - 容器の右余白をズームと同じ24px、下余白を8pxにして、ズームの真上8pxに右端を揃えて積まれるようにする
  - ボタンはFigma`1170:753`(default)/`1170:755`(active)のとおり42px角・白背景・枠`gray-200`・角丸8px・`shadow-card`で、`my_location`アイコン24pxを出す。取得中はアイコン色をcolor/primary、それ以外はcolor/textにする
  - 読み上げ名「現在地を表示」と押下状態で取得中かどうかを伝え、キーボードで押せるようにする。フォーカスの見た目は既存の地図ボタンと同じ規則に従う
  - 完了状態: フックをモックした結合テストで、ボタンの名前と押下状態がフックの状態に追従し、クリックとEnterで押せることが通る
  - _Depends: 1.1, 2.1_
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.6, 1.7, 1.8_

- [x] 3.2 ボタンの押下で取得を始め、現在地へ地図を移す
  - 未取得なら取得を始める。取得中で現在地があれば、取得を続けたまま縮尺を変えずに、Leaflet既定のアニメーション(0.25秒)で地図の中心を現在地へ滑らかに移す。取得中で現在地がまだ無い(許可待ち・初回測位待ち)ときは何もしない。取得を止める操作は持たない
  - フックの初回通知でも同じく縮尺を変えずに中心を滑らかに移す
  - サイトの動きの停止設定(`useMotionPreference().reduced`)が有効なときは、どちらの移動もアニメーション無しにする
  - 完了状態: 結合テストで、未取得での押下で開始が呼ばれる、取得中かつ現在地ありの押下で縮尺を保った中心移動が呼ばれ開始は呼ばれない、現在地なしの押下で何も起きない、初回通知で中心移動が呼ばれること、停止設定の有無で`animate`が`true`/`false`に切り替わることが通る
  - _Requirements: 2.2, 2.4, 2.5, 2.8_

- [x] 3.3 現在地マーカーをエリア名ラベルより手前の専用の層に描く
  - z-index 625の専用の層を作り、取得中かつ現在地があるときだけ精度円と点を描く
  - 精度円は端末が報告した精度(メートル)を半径にし、線color/location 1px、塗りcolor/location-accuracyで、縮尺に合わせて拡大縮小する(Figma`1170:759`)
  - 点は直径16px・白縁2px・塗りcolor/location・影(y=1、blur 3、黒30%)で、縮尺によらず大きさを保つ(Figma`1170:760`)
  - 精度円と点はどちらも操作を受け付けない層にし、ポリゴンの選択・地図の拡大縮小と移動を妨げない
  - 完了状態: 結合テストで、現在地があるときだけ描かれ、精度円の半径が精度と一致し、層のz-indexが625で、操作を受け付けない設定になっていることが通る
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5, 3.6_

- [x] 3.4 現在地を取得できなかったときに既存のトーストを出す
  - 失敗回数が1以上のとき、本文の直下に置いたボトムシート(1050)より手前・検索欄(1080)より奥の重なり順の容器に、「現在地を取得できませんでした」をリンク無しの既存トーストで出す
  - 失敗回数が増えるたびにトーストを出し直す
  - 完了状態: 結合テストで、失敗時に文言を持つ`role="status"`が本文の直下に出てリンクが無いこと、失敗回数が増えると出し直すことが通る
  - _Depends: 1.2_
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 4.5, 4.6, 4.7, 4.8_

- [x] 4. 構内マップへの組み込み
  - 構内マップの地図の中で、現在地のボタン・マーカー・トーストをズームコントロールの直後にマウントし、ズームより後に角へ追加されてズームの真上に積まれるようにする
  - 地図の既存のテストに現在地のモジュールのモックを足す
  - 完了状態: 地図のテストで現在地がズームより後にマウントされることが通り、`pnpm type-check`・`pnpm lint`・`pnpm test`がすべて通る
  - _Requirements: 1.1, 1.2, 1.6, 3.6_

- [x] 5. E2Eとブラウザでの確認
  - 共通: 開発サーバーは`make dev`でだけ起動し(`pnpm dev`などの直接起動は禁止)、ポート3000には触らない。E2Eは`make dev`が使うポートを`E2E_BASE_URL`に渡して実行する(既定値の3000へは向けない)。Playwrightを使ったら最後に必ず`browser_close`する。コミットはユーザーが実ブラウザで確認した後に行う
- [x] 5.1 現在地の表示と現在地への移動をE2Eで確かめる
  - 中心移動はアニメーションするため、点の位置は移動の完了を待ってから測る
  - 位置情報を許可し構内の座標を与えた状態でボタンを押すと、押下状態が取得中になり、点が画面中央付近に表示されることを確かめる
  - 地図をドラッグして現在地を画面外へ動かし、もう一度押すと点が画面中央付近に戻り、縮尺が変わらないことを確かめる
  - ページを開いただけでは位置情報を求めず、点もボタンの取得中の状態も出ないことを確かめる
  - 完了状態: 構内マップのE2Eに現在地表示のシナリオが加わり、`make dev`のサーバーに対して通る
  - _Requirements: 1.4, 1.5, 2.1, 2.2, 2.3, 2.4, 2.5, 3.1_

- [x] 5.2 ボタンの位置と取得失敗のトーストをE2Eで確かめる
  - SP(390x844)とPC(1440x900)で、ボタンの下端とズームの上端の差が8pxで右端が一致することを位置の実測で確かめる。エリア選択時と検索結果の表示中もボタンが表示されていることを確かめる
  - 構外の座標を与えた場合と、位置情報を許可しない場合のそれぞれで、「現在地を取得できませんでした」のトーストがリンク無しで出て、SPでは下端から80pxの位置にあり、ボタンが取得中でない状態に戻ることを確かめる
  - 完了状態: 構内マップのE2Eにボタン位置と取得失敗のシナリオが加わり、`make dev`のサーバーに対して通る
  - _Requirements: 1.1, 1.2, 1.6, 4.1, 4.2, 4.5, 4.6, 4.7, 4.8_

- [x] 5.3 ユーザーに実ブラウザで確認してもらい、確認後にコミットする
  - `make dev`のサーバーを立てたまま、構内マップのURLとFigmaの状態フレーム(現在地表示PC`1170:1230`/SP`1170:1264`、取得失敗SP`1170:1294`)をユーザーに渡し、実ブラウザで見てもらう。ポート3000には触らない
  - 自分で画面を確かめるためにPlaywrightを使った場合は、渡す前に`browser_close`する
  - 完了状態: ユーザーが実ブラウザで確認を済ませ、その後に変更がコミットされている

- [x] 6. プライバシーポリシーに位置情報の扱いを記載する

  - 本番CMSの管理画面で、固定ページのslug`privacy`の「1. 取得する情報」の末尾に「構内マップの現在地表示で使用する位置情報は、端末内でのみ処理し、当実行委員会へ送信しません。」の段落を足し、「制定・最終更新」の日付を反映した日に更新する。コードは変更しない
  - 完了状態: 本番の`/privacy`に段落と更新後の日付が表示されている
