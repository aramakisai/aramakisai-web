# Implementation Plan

- [ ] 1. 基盤: 並び順・一覧計測・閲覧履歴・GA4送信の土台
- [ ] 1.1 タブ単位のシードとカードの並べ替えを作る
  - タブ単位のシードを sessionStorage から読み、無いか整数として読めなければ乱数で作って保存する。保存できなくても、その表示の間だけ使えるシードを返す
  - シードとカードの id・カテゴリの組から決まる順に並べる。入力は変更しない。同じ入力からは常に同じ順になり、カードが増減しても残りのカード同士の相対順は変わらない
  - 本タスク以降で追加する jsdom のテスト(シード、一覧計測コンポーネント、履歴記録コンポーネント)をテスト設定の jsdom 対象に加える
  - 完了状態: 同じシードで同じ順、シードが違えば違う順、1枚除いても相対順が保たれる、保存済みシードの再利用、不正値の上書き、sessionStorage が例外を投げても数値を返す、の単体テストが通る
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.6_

- [ ] 1.2 (P) 一覧の種別とGA4アイテムへの変換を定義する
  - 一覧の種別として、企画一覧・トップページの注目企画・マイページのブックマーク・マイページの履歴の4つを定める
  - 表示順のカードと先頭の通し番号から、照合用のリンク先(既存の企画リンクの組み立てと同じ値)と、GA4のアイテム(企画id:カテゴリ、表示名、カテゴリ、1始まりの掲載位置)の組を作る。企業ブースのアイテムidはブースを示すカテゴリで作る
  - 完了状態: 先頭番号25を渡すと掲載位置が25から始まり、リンク先が実際のカードのリンクと一致する、の単体テストが通る
  - _Requirements: 5.1, 5.2, 5.3, 5.7_
  - _Boundary: ItemList_

- [ ] 1.3 (P) マイページの端末内保存に閲覧履歴を加える
  - 既存の保存に閲覧履歴の項目を加える(形式の版は変えない)。項目が無い既存データは空として読み、形式に合わない要素だけを除く
  - 記録: 同じ企画id・カテゴリの組があれば取り除いて先頭に入れ、20件を超えた古い分を捨てる。保存できなければ記録できなかったことを返す
  - 消去: 履歴を空にし、消去前の件数を返す
  - 記録・消去ともに既存の書き込み経路を通し、ブックマーク・スタンプ・端末の識別子をそのまま残す
  - 完了状態: 先頭追加、重複の移動、21件目で最古を捨てる、他の保存内容を変えない、保存不可の結果、消去件数、欠落・不正要素の読み込み、の単体テストが通る
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 3.7, 3.8_
  - _Boundary: MypageStorage_

- [ ] 1.4 (P) GA4の一覧計測・履歴消去のイベントとサイト内の参照元を加える
  - 一覧の表示、カードの選択、履歴の消去の3イベントを型付きで送れるようにする。パラメータは一覧の種別、絞り込みの有無(企画一覧のみ)、アイテム、消去件数とし、検索語・シード・端末の識別子は含めない
  - 直前に記録したページの位置を保持し、サイト内で2回目以降のページ閲覧に参照元として付ける。初回のページ閲覧には付けない。ページ閲覧を記録する契機は変えない
  - 完了状態: 初回は参照元なし、2回目は直前の位置、クエリ変更後は更新後の位置が参照元に入る、の単体テストが通り、送信条件(本番かつ測定ID設定時のみ)は既存のテストのまま通る
  - _Requirements: 5.5, 5.6, 5.8_
  - _Boundary: Analytics_

- [ ] 2. 一覧計測と履歴記録のコンポーネント
- [ ] 2.1 (P) 一覧の表示とカードの選択をGA4へ送るコンポーネントを作る
  - 包んだ一覧のアイテムの並びが前回の送信と異なるときだけ、一覧の表示イベントを1回送る。アイテムが無ければ送らない
  - 包んだ範囲のクリックで、押されたリンクのリンク先が一覧の項目と一致したときだけ選択イベントを送る。ブックマークボタン等では送らない
  - 余分な箱を作らず、包んだ一覧のレイアウトを変えない
  - 完了状態: 同じ項目で再描画しても1回だけ送る、カードのリンクで選択イベント、ブックマークボタンでは送らない、のコンポーネントテストが通る
  - _Requirements: 5.1, 5.2, 5.3, 5.4, 5.8_
  - _Boundary: ItemListTracker_
  - _Depends: 1.2, 1.4_

- [ ] 2.2 (P) 企画詳細ページの表示を閲覧履歴に記録する
  - 企画詳細ページで企画が見つかったときだけ、表示した企画id・カテゴリを閲覧履歴に記録するコンポーネントを置く。何も描画しない。企業ブース詳細には置かない
  - 記録できなかったときも何もせず、詳細ページの表示を続ける
  - 完了状態: マウント時と企画の切り替え時に1回ずつ記録し、保存不可でも例外を出さない、のコンポーネントテストが通り、詳細ページを開くと端末内保存に履歴が増える
  - _Requirements: 3.1, 3.8_
  - _Boundary: HistoryRecorder, DetailPage_
  - _Depends: 1.3_

- [ ] 3. 各画面への組み込み
- [ ] 3.1 企画一覧をタブ単位のランダム順で表示する

  - ページあたり件数・検索・絞り込み・ページ送り・URLの書き換えは変えない
  - 完了状態: 確定前は不可視、確定後に並べ替えた順で表示、絞り込み後も相対順を保つ、2ページ目の表示イベントの掲載位置が25から始まる、のコンポーネントテストが通る
