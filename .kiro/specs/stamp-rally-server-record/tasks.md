# Implementation Plan

- [ ] 1. 基盤: データベース・実行環境・認証基盤の準備
- [ ] 1.1 本番用と dev 用の D1 データベースを infra の Terraform に定義する
  - `aramakisai-infra` に本番 `aramakisai-stamps` と dev `aramakisai-stamps-dev` の 2 つを追加する
  - 適用 (`terraform apply`) は本番のアカウントへの変更なので、計画 (`plan`) の結果を示して承認を得てから `-target` で絞って行う
  - 適用後、2 つの `database_id` が確定し、D1 の一覧 API で 2 件が見える
  - _Requirements: 2.1, 8.2_

- [x] 1.2 スタンプと交換済み登録のスキーマをマイグレーションとして用意する
  - スタンプは匿名ID・企画id・カテゴリの組を主キーにし、主キー以外の索引を張らない
  - 交換済み登録は履歴として残し、取り消されていない登録が匿名IDごとに 1 件以下になる部分一意索引を張る
  - ローカルの D1 に適用でき、同じ組の 2 回目の挿入と、同じ匿名IDの有効な交換済み登録の 2 件目が DB で拒否される
  - _Requirements: 2.1, 2.2, 6.2, 6.3, 11.3, 11.4_

- [x] 1.3 Worker のバインディングと実行環境の読み取りを整える
  - D1・Analytics Engine・レート制限のバインディングと、OIDC の公開設定 (issuer・client id) を本番と dev の両方に定義する (dev への継承は無いので再掲する)
  - 実行環境の識別 (`prod`/`dev`/`preview`) は設定ファイルに置かず、デプロイ時の秘密値ファイルとローカル起動スクリプトから渡す。ローカル起動は `preview` を渡す
  - 実行環境の値が欠けているか不正なときは失敗として扱い、`preview` に落とさない
  - ローカル起動でバインディングを型付きで取得でき、値が欠けた状態では失敗が返るテストが通る
  - _Requirements: 7.5, 8.2_

- [ ] 1.4 公式サイトの管理者ログイン用の Zitadel アプリを宣言する
  - `aramakisai-infra` の Zitadel の投入定義に、本番と dev のコールバック URL を持つアプリを追加する
  - playbook の適用は本番の IdP への変更なので承認を得てから行い、発行された client secret は Infisical の `prod` にだけ登録する
  - 適用後、本番と dev のコールバック URL でアプリが認可リクエストを受け付ける
  - _Requirements: 7.1_

  - ブックマークの追加・削除の後も匿名IDが残ることをテストで確かめられる

- [x] 2.2 (P) スタンプと交換済み登録の読み書きを D1 に実装する

  - 同時に 2 件の交換済み登録で 1 件だけ成立し、取り消し後の再登録が新しい行になり、取り消し済みの再取り消しが既存の取り消し日時を返すことを、ローカル D1 の統合テストで確かめられる
  - _Requirements: 2.1, 2.2, 5.1, 6.1, 6.2, 6.3, 9.1, 11.1, 11.2, 11.3, 11.4, 11.5_

- [x] 2.3 (P) 交換用QRの署名の発行と検証を実装する

  - 発行直後は有効、300 秒後は期限切れ、別の匿名ID・改変・企画QRの署名は不正と判定されるテストが通る

- [x] 2.4 (P) 管理者セッションの発行と検証を実装する

  - 期限切れ・改ざん・形式不正は未ログインとして扱う
  - 改ざん・期限切れの Cookie が拒否されるテストが通る
  - _Requirements: 7.1, 7.4_
  - _Boundary: StaffSession_

- [x] 2.5 (P) 照会・集計・取得条件の判定を実装する
  - マイページのページにあるカタログから対象の組を作る処理を共有部品に移し、マイページ・署名発行・登録・管理者画面で同じものを使う
  - 匿名ID 1 件の要約 (スタンプ数・エリアごとの取得数) と、全体の集計 (参加端末数・交換済み数・組ごとの取得端末数と取得率・エリアごとの取得数と平均取得率・スタンプ数の分布) を作る。エリアの取得率はマイページと同じ規則で求める
  - カタログに無い企画・エリアの無い企画は「エリア不明」として数える
  - 公開中の全対象を取得しているかを判定する。対象が 0 件なら満たさない。公開されていない企画のスタンプは判定に使わない
  - 全取得・1 組欠け・対象 0 件・非公開企画のスタンプ・エリア不明の各場合の結果がテストで確かめられる
  - _Requirements: 3.1, 3.6, 4.1, 4.10, 5.1, 5.2, 5.4, 5.5, 6.4, 9.1, 9.2, 9.3, 9.4_
  - _Boundary: StampAggregate_

- [x] 2.6 (P) 計測の記録と匿名 API のレート制限を実装する

  - 接続元 IP ごとに 60 秒あたり 120 回の制限を判定する
  - 計測の点の構成と、制限超過の判定がテストで確かめられる

  - _Boundary: StampMetrics, RateLimit_
