# Implementation Plan

- [x] 1. CMS の試験運転の設定
- [x] 1.1 起点の記録と開催日の検証の判定
  - 試験内の開始日時が「送られていない」なら前の値を保持し、「null で送られた」なら試験内の開始日時と起点をともに消し、「日時で送られた」なら値が前回と同じでも起点をサーバーの現在時刻(秒未満切り捨て)にする
  - 試験内の開始日時の JST 日付が、開催日程の開場日時の JST 日付のどれかと一致するかを判定する。開催日が0件なら常に不一致
  - 単体テストが通る: 送信なしで保持、同値の再送信で起点を刻み直す、別の値、null で終了、秒未満の切り捨て、JST 日付の一致・不一致(日付の境目 00:00 / 23:59 を含む)、開催日0件
  - _Requirements: 1.4, 1.5, 1.6, 1.7, 1.10_

- [x] 1.2 サイネージ設定に試験運転の項目を追加し、保存時の判定と通知を結線する
  - サイネージ設定に試験運転のまとまり(試験内の開始日時、管理画面で非表示の起点)を追加する
  - 保存前の処理で 1.1 の判定を使い、日時で送られた保存でだけ開催日を検証して、開催日でなければ検証エラーで保存を拒む
  - 保存後の通知を、固定とスナップショットの両方に送るように変える
  - マイグレーションを生成して登録し、CMS とフロントエンドの型を再生成する(ローカル起動で消える importMap の Zitadel/S3 のエントリはコミットしない)
  - サイネージ設定の既存テストを、項目の構成と通知対象に合わせて更新して通る
  - マイグレーションを適用したローカル CMS で、実行委員が試験運転の日時を保存でき、開催日でない日付が 400 になる
  - _Requirements: 1.5, 1.6, 1.7, 1.9, 1.10, 2.4, 2.5_

- [x] 1.3 固定と試験運転の保存が互いを壊さないことの統合テスト
  - 固定の保存と試験運転の保存を交互に行っても互いの値が消えず、固定の保存で起点が変わらない
  - 試験中に開催日程を変えた後でも、スライドの無効化(固定の自動解除を伴う)が成功し、試験運転も続く
  - 試験内の開始日時を null で送ると終了できる
  - DB 統合テストが通る
  - _Requirements: 1.5, 1.7, 1.9, 1.10_

- [x] 2. CMS の試験運転パネル
- [x] 2.1 試験運転の状態の読み込みと保存
  - サイネージ設定の試験運転の値を読み込み、開始(試験内の開始日時だけを送る)と終了(null を送る)を保存する
  - スライド固定と同じく画面内で状態を共有し、保存中の二重保存を防ぎ、保存失敗を状態として持つ
  - 単体テストが通る: 読み込み、開始・終了の送信内容、保存中の二重保存の抑止、失敗時に保存前の状態を保つ
  - _Requirements: 1.4, 1.5, 1.7_

- [x] 2.2 一覧画面のパネル
  - サイネージ スライド一覧画面の、スライド固定の表示の直後に置き、見た目は固定の表示と同じ枠にする
  - 開催日の選択(表示は開催日のラベル、空なら開場日の月/日(曜))と分単位の時刻入力を置き、日付を選ぶたびに時刻をその日の開場時刻にする
  - 選んだ JST 日付と時刻から +09:00 付きの日時を組み立てて開始する
  - 停止中は「開始」、試験中は「試験中 M/D HH:MM」(現在の試験時刻を毎分更新)と「開始し直す」「終了」を出す。「開始し直す」は日時が同じでも押せる
  - 開催日が0件なら「開催日程が未登録です」、現実の日付が開催日なら「開催日のため試験運転は無効です」を出して開始系のボタンを無効にする(「終了」は押せる)。保存失敗は「保存できませんでした」
  - ローカル CMS の一覧画面でパネルが固定の表示の直後に出て、開始・開始し直し・終了が保存に反映される
  - _Requirements: 1.1, 1.2, 1.3, 1.6, 1.7, 1.8, 1.10, 1.11_

- [x] 3. フロントエンドの部品
- [x] 3.1 (P) スナップショットに試験のずれ量を載せる
  - スナップショットに、試験内の開始日時から起点を引いたずれ量(ミリ秒、試験中でなければ null)を追加する。サーバー時刻は実時刻のまま
  - 試験内の開始日時か起点が欠けている、または実時刻の JST 日付が開催日に当たるときは null にする
  - 単体テストが通る: 試験中のずれ量、未設定で null、片方欠けで null、開催日の実時刻で null
  - _Requirements: 2.1, 2.7_
  - _Boundary: SignageSnapshotData_
  - _Depends: 1.2_

- [x] 3.2 (P) 試験中の全画面表示
  - 全面に重ねる層で、中央に「試験中」を design.md の値(太字の表示用書体、280px、文字色トークン、不透明度15%)で出す
  - タップを下へ通し、読み上げ対象から外す
  - 部品の単体テストで、試験中だけ表示され、タップを妨げない指定になっている
  - _Requirements: 4.1, 4.3, 4.4_
  - _Boundary: SignageTrialOverlay_

- [x] 3.3 (P) タッチ操作のサブページでずれ量を受け取る
  - iframe 内で、同一オリジンの親画面からのずれ量の知らせだけを受け、最新のずれ量を持つ
  - タッチのタイムテーブルは、端末時計にずれ量を足した時刻で出演中を判定する
  - 非 null のずれ量を最初に受けた時点で、利用者がまだ日付を選んでいなければ、ずらした時刻で対象日を決め直す。選んだ後は上書きしない
  - 駐車場一覧は実時刻のまま変えない
  - 単体テストが通る: 別オリジン・別ウィンドウの知らせを捨てる、ずれ量を受けて対象日が試験日になる、利用者の選択後は上書きしない
  - _Requirements: 3.1_
  - _Boundary: TouchClockBridge_

- [x] 4. サイネージ画面への結線
- [x] 4.1 試験時刻と実時刻の振り分けと試験中表示の配置
  - 補正済み時刻を実時刻と試験時刻(実時刻の補正 + ずれ量)の2本にし、design.md の振り分け表どおりに渡す。バスの案内(運行日・発車・リアルタイム鮮度)、配信の期限、駐車場スライドの画像の古さは実時刻、それ以外とテロップは試験時刻
  - 試験中表示を、地震速報の全面表示より後ろ(最前面)に置く
  - 試験中でないときは2本の時刻が一致し、通常運転の表示が変わらない
  - 単体テストが通る: 開催日前の試験中にタイムテーブルスライドが巡回に入る、出演枠の開始通知が試験時刻で出る、バスの案内が実時刻のまま、試験中表示が試験中だけ出る、ずれ量が届くと再読み込みなしで切り替わり null で戻る
  - _Requirements: 2.2, 2.3, 2.4, 2.5, 2.6, 3.2, 4.1, 4.2_
  - _Depends: 3.1, 3.2_

- [x] 4.2 タッチ層からサブページへずれ量を送る
  - サブページから表示中のパスの知らせ(全ページが読み込みごとに送るもの)を受けた直後と、ずれ量が変わったときに、iframe へずれ量を送る
  - 単体テストが通る: パスの知らせを受けるとずれ量が送られる、ずれ量の変化で送り直す
  - _Requirements: 3.1, 3.2_
  - _Depends: 3.3, 4.1_
