# Implementation Plan

- [ ] 1. CMS の SEO フィールド基盤
- [ ] 1.1 サイト全体と各コレクションに任意の SEO フィールドを追加する
  - `festival_meta` にサイト既定の説明文・既定 OG 画像 (media への upload)・構造化データ用の会場住所を追加する
  - お知らせ・トピック・固定ページに説明文を、お知らせ・固定ページに OG 画像を追加する
  - 全フィールドを任意入力とし、日本語ラベルと編集者向けの用途説明を付ける。会場住所の値はコードに埋め込まない
  - 既存コレクションの定義流儀 (インライン定義・共通 helper なし) に合わせる
  - 完了状態: 管理画面の該当グローバル・コレクションで新フィールドが表示され、未入力のまま既存レコードを保存できる
  - _Requirements: 6.1, 6.2, 6.3, 6.4, 6.5, 6.6, 6.13_

- [ ] 1.2 差分マイグレーションを生成し、型を再生成する
  - `pnpm migrate:create` で差分マイグレーションを生成し、マイグレーション一覧に登録されていることを確かめる
  - ローカル Postgres にマイグレーションを適用し、既存データを保ったまま適用できることを確認する
  - `pnpm generate:types` を実行し、フロントエンド側の CMS 型定義まで同期する
  - 完了状態: マイグレーション適用と CMS の type-check / test が通り、フロントエンドの CMS 型に新フィールドが現れ、スキーマ差分チェックで破壊的変更が検出されない
  - _Requirements: 6.5, 6.7, 6.8, 6.12_

- [ ] 2. メタデータ合成の共通基盤
- [ ] 2.1 (P) 説明文の正規化処理を作る
  - 候補の先頭から最初の非空値を採り、HTML タグ除去・実体参照の最小デコード・空白正規化を行う
  - 120 文字を超える場合は末尾を省略記号付きで切り詰め、全候補が空なら指定の既定値を返す
  - 完了状態: HTML 除去・実体参照・空白・120 文字境界・全空時の既定値を検証する単体テストが通る
  - _Requirements: 1.7, 2.11, 6.10_
  - _Boundary: MetaDescription_

- [ ] 2.2 既存の取得関数が SEO 用の値を返すよう拡張する
  - 祭情報の取得結果にサイトタイトル・既定説明文・既定 OG 画像・会場名・会場住所・SNS リンクを加える (取得回数は増やさない)
  - お知らせ・トピックの要約に説明文・更新日時を、お知らせには OG 画像を加える
  - 固定ページの取得結果に説明文・OG 画像・更新日時を加える
  - 既存の呼び出し側が変更なしで型検査を通ることを確認する
  - 完了状態: 拡張後のマッパーが新フィールドを詰めること、未設定時に null になることを検証するテストが通る
  - _Depends: 1.2_
  - _Requirements: 6.9, 4.3_

- [ ] 2.3 お知らせ・トピックの詳細取得を公開済みに限定する
  - 詳細取得でも一覧取得と同じ公開済み条件を使い、ID 一致と組み合わせて 1 回の取得で判定する (公開済み判定を再定義しない)
  - 未公開・不在・取得失敗はいずれも「無し」として返し、呼び出し側の not found とメタデータの既定値退避がそのまま働くようにする
  - 完了状態: 公開済みは返り、公開日時が未設定・未来のものは無しになることを検証する単体テストが通り、未公開記事の詳細 URL が not found になる
  - _Requirements: 8.8, 8.9_

- [ ] 2.4 サイト既定メタデータの解決処理を作る
  - サイトタイトルを `site_title` → 祭名 → 固定値「荒牧祭」の順で決め、開発環境では「【開発環境】」を前置する
  - 既定説明文を CMS の既定説明文 → 祭概要の正規化結果 → 固定値の順で決める
  - 既定 OG 画像を CMS 配信 URL に解決し、構造化データ用に祭情報を保持する
  - CMS 取得に失敗しても例外を出さず固定値へ退避する
  - 完了状態: タイトル 3 段の退避・開発環境の前置・説明文の退避・取得例外時の退避を検証する単体テストが通る
  - _Requirements: 1.4, 1.5, 1.6, 1.7, 1.8, 1.9, 8.1, 8.6_

- [ ] 2.5 ページメタデータの一括合成処理を作る
  - ページ固有の値とサイト既定値から、openGraph (サイト名・ロケール・種別・URL・タイトル・説明・画像) と twitter (大画像カード) を毎回完全な形で返す
  - クエリを含まない正規パスから canonical を設定し、root layout では出さない。インデックス・リンク追跡の可否は root でのみ設定する
  - OG 画像をページ個別 → 本文の画像 → サイト既定 (CMS) → 同梱の静的既定画像の順に採用し、静的既定画像には 1200×630 を宣言する
  - 画像 URL は CMS 配信 URL または `NEXT_PUBLIC_SITE_URL` 基準の絶対 URL とし、静的既定画像の実在は検査しない
  - 完了状態: openGraph 全キーの存在・画像優先 4 段・静的既定画像の寸法宣言・canonical の有無を検証する単体テストが通る
  - _Requirements: 1.1, 1.2, 1.3, 1.10, 1.11, 6.11, 7.1, 7.2, 7.3, 7.4, 7.5_

- [ ] 2.6 (P) コード定義ルートの title と description を定める
  - トップ・お知らせ一覧・企画一覧・トピック一覧・構内マップの title と description を定数として持つ (トップの title はサイトタイトルそのもの)
  - 文言は各ページの見出しと揃える
  - 完了状態: 5 ルート分の定数が型付きで定義され、説明文が 120 文字以内であることをテストで確認できる
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5_
  - _Boundary: RouteMetadata_

- [ ] 3. クロール制御と sitemap
- [ ] 3.1 (P) 公開フェーズに従う robots.txt を配信する
  - クローラ向けの実効フェーズを `BUILD_PHASE` から決め、既存の公開パス一覧・前方一致一覧から allow / disallow を導出する (一覧を再定義しない)
  - 開催前はゲート対象を除外し、描画資産は許可する。開催中はサイト全体を許可する。どちらもゲートの rewrite 先は除外する
  - sitemap の絶対 URL を宣言する
  - 完了状態: `/robots.txt` が応答し、開催前・開催中それぞれの出力と sitemap URL の絶対化を検証するテストが通る
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 1.11, 8.5_
  - _Boundary: CrawlTargets, RobotsRoute_

- [ ] 3.2 sitemap 用の取得処理を追加する
  - 公開済み企画 × 選択カテゴリの URL と更新日時を、追加の結合取得なしで列挙する (企画名が空のものは除外)
  - 構内マップを構成するコレクション (区画・ステージ・公演枠・公開済み企画) の最大更新日時を取得する
  - 指定 slug の固定ページについて実在と更新日時を取得する
  - 完了状態: 各取得処理が期待どおりの URL と更新日時を返し、公開済みのみを対象とすることを検証するテストが通る
  - _Requirements: 4.2, 4.4, 4.6, 4.7, 4.9_

- [ ] 3.3 sitemap を公開範囲と実在ページに合わせて書き換える
  - 実効フェーズで公開と判定されるページだけを列挙し、お知らせ・トピック・企画の詳細と構内マップを公開判定に従って載せる
  - 全エントリに更新日時を設定する。構内マップは構成コレクションの最大更新日時とし、全取得失敗時のみ省略する
  - 公開日時が未設定のレコード、`pages` に実在しない固定ページ、ルート実体の無いパスは載せない
  - 各取得の失敗は独立に扱い、取得できた範囲で応答する
  - 完了状態: 開催前に企画・トピックが出ない、開催中は出る、CMS 失敗時に 500 にならない、実体の無いパスが出ない、更新日時の源が正しいことを検証するテストが通る
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 4.5, 4.6, 4.7, 4.8, 4.9, 1.11, 8.5_

- [ ] 4. 構造化データ
- [ ] 4.1 (P) JSON-LD を安全に出力するコンポーネントを作る
  - JSON を直列化し、script 要素を閉じる文字列が混入しても無害化されるようにする
  - 完了状態: `</script>` を含む文字列を渡しても script が途中で閉じないことを検証するテストが通る
  - _Requirements: 5.10_
  - _Boundary: JsonLd_

- [ ] 4.2 Event / Organization / BreadcrumbList の組み立て処理を作る
  - Event は開催日程から開始・終了日時を、会場名と会場住所から場所を導出し、名称・説明・画像・URL・主催者を設定する。日程が無ければ出力しない
  - Organization は荒牧祭実行委員会を記述し、SNS リンクがあれば sameAs に列挙する
  - BreadcrumbList はトップからの階層 (お知らせ・トピック・企画・固定ページ) を出力する
  - CMS の値が欠けたプロパティは省略し、全体の出力は止めない
  - 完了状態: 日程空で Event が null、住所未設定で address 省略、sameAs の列挙、パンくず階層を検証する単体テストが通る
  - _Depends: 2.4_
  - _Requirements: 5.1, 5.2, 5.3, 5.4, 5.5, 5.6, 5.7, 5.8, 5.9_

- [ ] 5. ページへの組み込み
- [ ] 5.1 root layout のメタデータを共通基盤に置き換える
  - サイト既定値の解決と一括合成を使い、タイトルのテンプレート合成と開発環境の前置を維持する
  - 完了状態: root layout が openGraph / twitter / robots / 既定 description を出力し、既存の layout テストを更新した上で通る
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 1.6, 1.7, 1.8, 1.9_

- [ ] 5.2 (P) トップ・一覧・構内マップにメタデータと JSON-LD を付与する
  - トップ・お知らせ一覧・企画一覧・トピック一覧・構内マップに固有の title / description / canonical を設定する。クエリを受け取る一覧でも canonical にクエリを含めない
  - トップで Event と Organization を 1 つの JSON-LD にまとめて出力する
  - 完了状態: 各ページの metadata が期待する title / description / canonical / openGraph を返し、トップに ld+json が含まれることを検証するテストが通る
  - _Depends: 2.5, 2.6, 4.1, 4.2_
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.5, 2.9, 1.10, 5.1, 5.5, 8.4_
  - _Boundary: トップ・一覧・マップの各ページ_

- [ ] 5.3 (P) 詳細ページのメタデータを共通基盤に置き換え、パンくずを付与する
  - お知らせ・トピック・固定ページ・企画の詳細で、ページ固有の説明文 → 本文 → サイト既定値の順に description を決め、openGraph と canonical を出す
  - ページ本体と同じ取得関数を使い、メタデータのためだけの往復を増やさない
  - 取得結果が無い・失敗した場合も例外を出さずサイト既定値で返し、本文側の挙動 (not found) とは切り離す
  - 各詳細に BreadcrumbList を出力する
  - 完了状態: 4 種の詳細で期待する title / description / openGraph が生成され、CMS 取得失敗時に既定値へ退避し、パンくずが出力されることを検証するテストが通る
  - _Depends: 2.2, 2.3, 2.5, 4.1, 4.2_
  - _Requirements: 2.6, 2.7, 2.8, 2.10, 1.10, 5.7, 6.9, 6.10, 8.1, 8.2, 8.3, 8.4, 8.6_
  - _Boundary: 詳細ページ 4 種_

- [ ] 6. 検証
- [ ] 6.1 フロントエンドの品質ゲートを通す
  - `pnpm type-check` / `pnpm lint` / `pnpm test` / `pnpm build` をフロントエンドで実行する
  - 完了状態: 4 コマンドが全て成功する
  - _Requirements: 8.7_

  - 各ページの `<head>` を取得し、og:* / twitter:* / canonical / ld+json の存在と、`og:image` / `twitter:image` が CMS 画像または静的既定画像の絶対 URL を指すことを確認する
  - `/robots.txt` と `/sitemap.xml` が公開範囲どおりであることを確認する
  - 構造化データの検証ツールでトップの Event と詳細の BreadcrumbList に必須プロパティ欠落の重大エラーが無いことを確認する
  - 完了状態: 上記確認結果を PR に記録できる状態になっている
  - _Requirements: 7.6, 5.9_
