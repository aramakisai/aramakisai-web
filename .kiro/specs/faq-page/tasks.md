# Implementation Plan

- [ ] 1. 基盤: FAQの取得とルート定義
- [ ] 1.1 faq_itemsを表示順で全件取得する取得関数を作る
  - CMSの`faq_items`を表示順の昇順・件数上限なし・関連展開なしで取得し、ID・質問・回答・更新日時だけの表示用の形に整形して順序を保って返す
  - 公開状態による絞り込みは付けない(`faq_items`は公開状態を持たない)
  - 取得失敗時は例外を投げ、扱いは呼び出し側に委ねる(トピック一覧の取得関数と同じ規約)
  - 単体テストで、取得条件の受け渡し・順序を保った整形・失敗時の例外が検証され通る
  - _Requirements: 1.2, 2.1, 2.2_

- [ ] 1.2 (P) `/faq`のルートメタデータを登録する
  - コード定義ルートに`/faq`を加え、タイトル「よくある質問」と説明文「荒牧祭についてよくある質問と回答をまとめています。」を定義する
  - ルート一覧を完全一致で検証している既存テストに`/faq`を加える
  - 型チェックとルートメタデータのテストが通り、他ページのメタデータ定義に変化が無い
  - _Requirements: 4.1_
  - _Boundary: ROUTE_METADATA_

- [ ] 2. コア: 一覧部品・sitemap・背景図形の部品
- [ ] 2.1 (P) 質問と回答を開閉できる一覧部品を作る
  - 先頭と各項目の下に区切り線を置き、各項目をブラウザ標準の開閉要素(質問を押す行+回答)で描く。初期状態は全閉で、同時に複数開ける
  - 回答はHTMLとして解釈しないテキストとして描き、入力された改行を保つ。回答の左に成功色の2pxの開状態マーカーを付ける
  - 質問行・回答・区切り線の寸法・文字指定・色・開閉アイコンはFigma(ファイル`0kWDqHsLr6xE8b4FFgR1Zx`、FaqItem `631:576`、closed `631:562`、open `631:568`)を実測して当て、既定の三角を消してフォーカス表示を既存UIに揃える
  - アイコンの回転と回答の展開を既存UIと同じ時間・緩急でアニメーションさせ、モーション抑制(OS設定とフッターの切替の両方)で無効になる。回答の展開は開閉要素自身の開状態で切り替える(子孫向けの指定では効かない)
  - 単体テストで、区切り線の本数と位置、`open`・`name`属性が無いこと、質問の配置、改行を保ち HTML が解釈されない回答が検証され通る
  - _Requirements: 1.2, 1.3, 1.4, 1.5, 1.8_
  - _Boundary: FaqList_

- [ ] 2.2 (P) sitemapで`/faq`をfaq_items由来のエントリとして掲載する
  - `/faq`を固定ページ候補から外し、`pages`に同じslugのレコードが無くても掲載する
  - 現在のクロール時フェーズで`/faq`が公開対象のとき、取得関数の結果から各項目の更新日時の最新を最終更新日時とする。0件なら最終更新日時なしで載せる
  - 取得失敗時は`/faq`のエントリだけを欠落させ、他のエントリは通常どおり返す
  - `pages`から`/faq`を掲載していた既存テストの前提を書き換え、FAQ取得関数をモックして既定を0件にする
  - 最新日時・0件・失敗・`pages`未登録(固定ページの更新日時の取得対象に`faq`が含まれないこと)の各ケースのテストが通る
  - _Requirements: 5.1, 5.2, 5.3, 5.4, 5.5_
  - _Boundary: sitemap_
  - _Depends: 1.1_

- [ ] 2.3 (P) 背景図形の除外対象に開閉行を加える
  - 開閉要素の質問行全体を、背景図形が避ける対話要素に含める
  - 単体テストで質問行の矩形が除外矩形として集められることが検証され通る
  - _Requirements: 1.5_
  - _Boundary: exclude-rects_

- [ ] 2.4 (P) 背景図形の配置計算に帯の追加配置と違反判定を加える
  - 切り出しの前に、固定入力を数通り用意して現行の配置結果を期待値として記録するテストを加える
  - 既存の配置ループと候補生成の縦位置の範囲を引数化し、既存の配置関数は全ページ範囲で呼んで乱数の消費順と結果を変えない
  - 基準配置の直後から同じ乱数列を続け、基準のフッター上端から下を440pxの帯に区切って帯ごとの図形を返す関数を加える。帯の図形は除外矩形を使わず、基準配置と先行する帯との間隔だけで決める。個数は現行の式を帯の高さに当てる(下限なし)
  - 図形の配列に対し、除外矩形との重なり(配置時と同じ外接矩形と10pxのマージン)とページ範囲外を図形ごとに返す関数を加え、リングの組はどちらかが違反したら組ごと違反とする
  - 単体テストで、記録した期待値との一致、帯の関数の決定性、帯数を増やしても先行する帯が変わらないこと、組とページ範囲を含む違反判定が検証され通る
  - _Requirements: 1.5, 1.8_
  - _Boundary: background-shapes lib_

- [ ] 3. 統合: ページと背景図形の組み込み
- [ ] 3.1 `/faq`ページを`(site)`ルートグループに追加する
  - 共通ヘッダー・フッター配下のページとして、ルートメタデータのタイトル・説明文、canonicalとOGPのURL`/faq`を既存一覧ページと同じ形式で出す
  - 取得関数の失敗は空配列として扱い、0件と同じく主見出しの下に「よくある質問はありません」を表示し、200で応答する
  - トップ→よくある質問の2階層のパンくず構造化データを出し、FAQPageの構造化データは出さない
  - 外側の余白は既存一覧の余白指定だけを流用し、見出しとの間隔は本文列で持って項目の有無で切り替える(一覧時と0件時で間隔が違う)
  - 外側の余白・本文列幅・見出しと一覧の間隔・0件文言の指定はFigma(ファイル`0kWDqHsLr6xE8b4FFgR1Zx`、`633:35`、`634:165`、`635:394`、`635:305`)を実測して当てる。主見出しはページのh1とし、見た目はFigmaの値に合わせる
  - 統合テストで、見出し・全件表示・失敗と0件の同一表示・パンくず2階層とFAQPage不在・メタデータのタイトル・説明・canonicalが検証され通る(200応答は4.1の実機で確認)
  - _Requirements: 1.1, 1.2, 1.6, 1.7, 2.3, 3.1, 3.2, 3.3, 4.1, 4.2, 4.3, 4.4_
  - _Depends: 1.1, 1.2, 2.1_

- [ ] 3.2 背景図形コンポーネントで同じ幅での高さ変化を配置し直さずに扱う
  - 計測処理を「計測」と「配置」に分け、最初の計測の入力と結果(パス・幅・ページ高・除外矩形・図形・ヘッダー高さ・セクション・装飾可能な下端)を基準として保持する。パスまたは幅が変わったときは現行どおり基準を取り直して全図形を配置し直す
  - 同じ幅で高さや文字位置が変わったときは基準を更新せず、現在の除外矩形とページ範囲に違反する図形だけを非表示にし、解消したら元の位置に戻す。既存の図形は入場をやり直さない
  - 同じ幅での再配置を前提にしている既存のコンポーネントテストを新しい挙動に合わせて書き換える
  - コンポーネントテストで、同じ幅の再計測で位置が変わらず違反した図形だけ隠れること、幅の変化で配置し直すことが検証され通る
  - _Requirements: 1.5, 1.8_
  - _Depends: 2.3, 2.4_

- [ ] 3.3 背景図形コンポーネントで伸びた範囲に帯の図形を描き足す
  - 現在のフッター上端までに掛かる帯数を求め、生成済みの帯を保持して増えた分だけ取り込み、帯ごとの別リストとして本文レイヤーに描き足す。既存の帯は入場をやり直さない
  - 帯の図形にも違反判定を適用し、縮んで範囲外になった帯はアンマウントせず全図形を非表示にする
  - コンポーネントテストで、高さが伸びると帯の図形が足され、戻ると隠れ、再び伸びても既存の帯が入場をやり直さないことが検証され通る
  - _Requirements: 1.5, 1.8_
