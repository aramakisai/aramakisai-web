# Implementation Plan

- [x] 1. 送信の基盤
- [x] 1.1 送信モジュールを全イベント共通の唯一の送信経路にする
  - 機能ごとのイベント名と、共通の項目名(結果・手段・時間・件数・指標値)を型として定義し、既存のQRスタンプ・ブックマークの送信もこの型に載せる
  - 本番・測定IDあり・サイネージ以外の3条件がすべて真のときだけ送り、それ以外はdataLayerに何も積まない
  - どの送信が最初に呼ばれても、初期化(js・ページURLの設定・page_viewを自動送信しない設定)をイベントより先に1回だけ積む
  - 送るページURLは検索キーワードのクエリとハッシュを除いた形に整え、すべての独自イベントに付ける
  - page_viewの送信と、load後のアイドル時にgtag.jsを1回だけ読み込む処理を用意する。内部の例外は呼び出し元へ伝えない
  - 完了時: 単体テストで、送信不可の3条件でdataLayerが空、初期化がイベントより先に積まれる、キーワードとハッシュが除かれ`category`・`page`が残る、gtag.jsの読み込みが1回だけ、を確認できる
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 1.5, 2.1, 2.2, 5.1, 6.4, 8.1_

- [x] 1.2 端末の対応状況を判定する
  - 端末内保存の可否、Web Share・クリップボード書き込み・位置情報・ダイアログ要素への対応、ホーム画面からの起動、OSの動きを減らす設定、PC向け入力環境を、固定のキーで「1/0」として返す
  - PC向け入力環境の判定条件は、既存のスタイルの判定条件と同じ文字列にする
  - 完了時: 単体テストで各判定の真偽と、PC向け入力環境の条件がスタイル側と一致することを確認できる
  - _Requirements: 4.1, 8.2, 16.2_

- [x] 2. GA4の読み込みとページ単位の送信
- [x] 2.1 GA4の読み込み・page_view・Web Vitals・端末対応状況を1つの部品で送る
  - マウント時にgtag.jsの遅延読み込みを始める。サイネージ・本番以外・測定ID未設定では何もしない
  - パスが変わったときだけpage_viewを送り、クエリ変化(絞り込み・ページ番号)ではページURLの設定だけを積む。ハッシュの変化は扱わない
  - Web Vitalsは5指標だけを、最初に描画したときのパスと合わせて送る
  - 端末の対応状況は、タブ内の保存領域で1回に抑えて送る。保存領域が使えない端末では読み込みごとに送る
  - 完了時: 部品のテストで、パスの変化でpage_viewが積まれ、クエリ変化ではURLの設定だけが積まれること、再描画でWeb Vitalsの監視が登録し直されないこと、Web Vitalsが5指標だけであること、端末の対応状況が1回に抑えられることを確認できる
  - _Requirements: 2.1, 3.1, 3.2, 4.1, 4.2, 6.1, 6.2, 6.3, 6.4, 6.5_
  - _Depends: 1.2_

- [x] 2.2 ルートレイアウトと全体エラー画面に読み込み部品を置く
  - ルートレイアウトの既存のgtag.js・初期化スクリプトを、新しい部品に置き換える(検索パラメータを読むため、描画の待機境界で包む)
  - 全体エラー画面にも同じ部品を置き、ルートレイアウトを通らない画面でもGA4が読み込まれるようにする
  - 完了時: ルートレイアウトのテストで旧スクリプトが無く新しい部品が置かれていること、型チェックとビルドが通ることを確認できる
  - _Requirements: 2.2, 5.1, 18.3_
