# Requirements Document

## Project Description (Input)

企画 (出展物) の一覧ページと詳細ページをフロントエンドに実装する。Payload CMS の Exhibitions コレクションを参照する。

### 一覧ページ

外観:

- カード型レイアウト
- カードに表示する項目
  - サムネイル (企画の写真リストの先頭から取得)
  - 場所
  - タイトル
- ページネーション

機能:

- ファセット検索
- 自由記述検索

### 詳細ページ

外観:

- 写真リストと拡大画像 (EC サイト的なギャラリー)
- タイトル
- 場所
- 出展団体名
- 共有ボタン
- カテゴリ
- 紹介文
- SNS・ホームページへのリンク
- 場所を示すマップ

機能:

- マップ表示は構内マップ機能 (`campus-map`) のコンポーネントを流用する
- 共有リンクの生成
- 投票機能 (検討事項)
- ブックマーク機能 (検討事項)

### 参照するデータソース

Payload CMS の `student_exhibitions` コレクション。未認証では `status=published` のレコードのみ読める。

既存フィールドとの対応:

- サムネイル・ギャラリー: `images` (先頭がサムネイル)
- タイトル / 出展団体名: `name` / `organization_name`
- 出演用の企画名: `stage_name` を新設する (text、任意、最大 255 文字)。カテゴリに `stage` を含むときだけ管理画面に表示し、ステージ文脈 (タイムテーブル、出演枠に紐づく表示) で企画名として使う。未入力なら `name` にフォールバックする。既存フィールドを変えない純粋な追加のため `cms-schema-check` の破壊的変更には当たらない
- カテゴリ: `category` (複数選択。値は英語のため表示用の日本語ラベル対応を FE に持つ)
- 場所: 展示・出店は `area_id` (`map_areas.name`) + `booth_label`、ステージ企画は `performance_slots` → `stages` のステージ名
- 紹介文: `description` (textarea、DB は長さ制限なしの `varchar`) を企画の紹介文として使う。管理画面の説明文「一覧表示用短文」は実態に合わないため「企画の紹介文」に改める (DB スキーマは変わらない)
- SNS・ホームページリンク: 既存の `links` は `type: 'json'` で形が未定義のため、出展者が管理画面で JSON を手書きする必要があり、URL の検証もない。これを `array` フィールド (各行 `platform` select: x / instagram / facebook / youtube / tiktok / line / website、`url` text: `https://` のみ許可) に置き換える。表示名は持たず、詳細ページではアイコンのみで表示する。`json` → `array` は型変更のため `cms-schema-check` の破壊的変更検出対象となるが、本番の `student_exhibitions` は 0 件のためデータ移行は不要 (2026-09-18 時点で本番 DB を確認済み)

### 関連 spec

- **本 spec に依存するもの**
  - `campus-map`: ポリゴンをクリックして表示した出展物リストから、本 spec の詳細ページへ遷移する。詳細ページの URL 設計が前提となる
  - `responsive-navigation`: 下部ナビゲーションの「企画一覧」導線の遷移先
  - `digital-signage`: 企画データの表示に本 spec のデータ取得層を流用する想定
  - `timetable-page`: 出演枠から遷移する詳細ページの URL 設計が前提となる。出演時間を持つ企画への時間情報表示とタイムテーブルへのリンクも `timetable-page` 側で追加する
- **本 spec が依存するもの**
  - `campus-map` (部分的): 詳細ページのマップ表示コンポーネント。ただし詳細ページのマップは後追いで組み込めるため、本 spec を先行させる

### 決定事項

- 投票機能・ブックマーク機能はスコープ外。投票は認証・不正対策を伴うため別 spec、ブックマークは localStorage で後付け可能
- ファセット検索の対象はカテゴリとエリア。出展団体名は自由記述検索の対象に含める
- 検索・ファセット・ページネーションはサーバーサイドで行う (URL クエリ `?q=&category=&area=&page=` を読んで絞り込んだ結果を返す)。URL 共有・SEO・初期ペイロードを同時に満たすため。1 ページ 24 件
- 詳細ページの URL は `/exhibitions/[id]`
- 一覧の並び順は ID 昇順のみ。並び替え機能は設けない
- エリアでの絞り込みは実装側で解決する。企画に直接設定されたエリアに加え、出演ステージが属するエリアも対象に含める (運用でステージを `map_areas` に二重登録しない)
- 1 企画 1 レコード (`owner` の UNIQUE 制約) は維持する。出店と出演を兼ねる団体はカテゴリを複数選択して表現する。出店と出演で名前を分けたい場合に備え、出演用の企画名 `stage_name` を新設する (レコードは 1 件のまま、ステージ文脈だけ別名で表示する)
- 見出し色 `primary` は変更しない。見出しは装飾要素としてコントラスト基準の対象外とする
- 共有ボタンは Web Share API、非対応環境ではリンクコピーにフォールバックする
- 詳細ページのマップは `campus-map` 実装後に組み込む
- 企画カード: テーマ「万彩」に合わせ、サムネイルと企画名を外枠で 1 枚にまとめ、カード背景を企画名を seed にした決定的な乱数によるグラデーションにする。色は `tailwind.config.ts` の既存カラーのみ。同じ企画名は常に同じ配色になる (SSR とクライアントで一致させる)。反対色の組み合わせで中間がくすまないよう OKLCH 色空間で補間する。並び順による暖色の連続は対策しない。カードは枠線なし、影は hover 時のみ。カード上の文字・アイコンはグラデーション背景上で WCAG AA のコントラスト (文字 4.5、アイコン 3) を満たす色にする。画像なし企画はサムネイル領域を灰色で塗り、画像なしアイコンを重ねる (画像ありカードとの統一感を優先)
- ページ背景: `tailwind.config.ts` の `background` を `#ffffff` から暖色寄りの白 `#fbf8f3` に変更する (サイト全体に波及する)。グレーは背景と調和させるため Tailwind 標準の `gray` ではなく暖色寄りの `stone` を使う
- アイコン: UI アイコンは Material Symbols Sharp (weight 300)、SNS アイコンは各サービスの公式ロゴを色も含めてそのまま使う (ブランドガイドライン準拠)。見出しの明朝体と調和させるため丸みのあるアイコンセットは使わない。既存の `frontend/src/components/sns-icon.tsx` (ヘッダー・フッターで使用) も本 spec で同方針に置き換え、サイト内のアイコンを統一する
- 画面デザインは Figma ファイル「ホームページ」の「企画ページ」ページ (https://www.figma.com/design/0kWDqHsLr6xE8b4FFgR1Zx?node-id=2-3) を正とする

## Introduction

来場者が学生企画を探し、個々の企画の詳細を確認できるよう、フロントエンドに企画一覧ページと企画詳細ページを追加する。一覧ではカテゴリ・エリアによる絞り込みと自由記述検索で目的の企画を見つけられ、詳細では写真・場所・紹介文・団体の SNS やホームページへのリンクを確認し、企画を他者へ共有できる。

あわせて、出展者が CMS 管理画面で SNS・ホームページのリンクを入力しやすく安全な形で登録できるようにデータ構造を改め、テーマ「万彩」に沿ったカード配色・ページ背景・アイコンの統一をサイト全体の基盤として導入する。本 spec は Figma によるデザイン管理を導入する最初の spec であり、画面デザインは Figma ファイル「ホームページ」を正とする。

## Boundary Context

- **In scope**:
  - 企画一覧ページ (`/exhibitions`) と企画詳細ページ (`/exhibitions/[id]`)
  - 一覧の自由記述検索・カテゴリ/エリアによる絞り込み・ページ送り
  - 企画カード (他 spec から再利用される表示部品)
  - 企画の共有
  - `student_exhibitions.links` のデータ構造変更 (本番は 0 件のためデータ移行は不要)
  - ページ背景色・グレーの色味・アイコンセットのサイト全体での統一 (既存のヘッダー・フッターの SNS アイコン置き換えを含む)
- **Out of scope**:
  - 投票機能・ブックマーク機能
  - 詳細ページへの構内マップ表示 (`campus-map` 実装後に組み込む)
  - タイムテーブルへの導線 (`timetable-page` 実装後に組み込む)
  - サイト共通ヘッダー・フッターのレイアウト変更 (アイコンの置き換えのみ行う)
  - `festival_meta.sns_links` のデータ構造変更
- **Adjacent expectations**:
  - `campus-map` は本 spec の企画カードと詳細ページ URL を利用する
  - `responsive-navigation` は企画一覧ページを遷移先とする
  - `digital-signage` は本 spec の企画データ取得・整形を利用する
  - `timetable-page` は詳細ページ URL を遷移先とする

## Requirements

### Requirement 1: 企画一覧の表示

**Objective:** As a 来場者, I want 公開されている企画をカードで一覧したい, so that 祭にどんな企画があるかを把握できる

#### Acceptance Criteria

1. When 利用者が `/exhibitions` を開いたとき, the 企画一覧ページ shall 公開状態 (`published`) の企画だけを企画カードとして表示する
2. The 企画一覧ページ shall 企画を ID の昇順で並べる
3. The 企画一覧ページ shall 1 ページあたり最大 24 件の企画を表示し、残りをページ送りで辿れるようにする
4. The 企画一覧ページ shall 条件に一致する企画の総件数と、現在表示している範囲 (例: 「30 件中 1-24 件」) を表示する
5. The 企画一覧ページ shall PC 幅では複数列、スマートフォン幅では 1 列でカードを並べる
6. If CMS から企画データを取得できない場合, the 企画一覧ページ shall 空の一覧ではなく、取得に失敗したことが分かる表示を行う
7. If 公開状態の企画が 1 件もない場合, the 企画一覧ページ shall 企画がまだ公開されていない旨を表示する

### Requirement 2: 企画の検索と絞り込み

**Objective:** As a 来場者, I want キーワード・カテゴリ・エリアで企画を絞り込みたい, so that 目的の企画を素早く見つけられる

#### Acceptance Criteria

1. When 利用者が検索欄にキーワードを入力したとき, the 企画一覧ページ shall 企画名または出展団体名にキーワードを含む企画だけを表示する
2. The 企画一覧ページ shall キーワードの照合で全角/半角および英字の大文字/小文字の違いを区別しない
3. When 利用者がカテゴリの選択肢を選んだとき, the 企画一覧ページ shall 選んだカテゴリのいずれかに属する企画だけを表示する
4. When 利用者がエリアの選択肢を選んだとき, the 企画一覧ページ shall 選んだエリアのいずれかに配置された企画だけを表示する
5. The 企画一覧ページ shall エリアの判定に、企画に直接設定されたエリアと、企画の出演ステージが属するエリアの双方を用いる
6. When キーワード・カテゴリ・エリアのうち複数の条件が指定されたとき, the 企画一覧ページ shall すべての条件を同時に満たす企画だけを表示する
7. The 企画一覧ページ shall エリアの選択肢を CMS に登録されたエリアから構成し、カテゴリの選択肢を日本語の表示名 (ステージ / 展示 / 出店 / その他) で表示する
8. When 検索条件が変更されたとき, the 企画一覧ページ shall 表示を 1 ページ目に戻す
9. When 検索条件またはページ番号が変わったとき, the 企画一覧ページ shall その状態を URL に反映し、同じ URL を開いた利用者に同じ検索結果とページを表示する
10. If 条件に一致する企画が 1 件もない場合, the 企画一覧ページ shall 該当する企画がない旨を表示する
11. If URL で指定されたページ番号が存在する範囲外の場合, the 企画一覧ページ shall 有効な範囲のページを表示する

### Requirement 3: 企画カード

**Objective:** As a 来場者, I want テーマに沿った見やすいカードで企画を見分けたい, so that 一覧を楽しく眺めながら企画を選べる

#### Acceptance Criteria

1. The 企画カード shall サムネイル・場所・企画名を 1 枚のカードにまとめて表示し、サムネイルをカードの上端・左右端まで余白なく配置する
2. The 企画カード shall 企画の写真のうち先頭の 1 枚をサムネイルとして表示する
3. If 企画に写真が登録されていない場合, the 企画カード shall サムネイル領域を灰色で塗り、画像がないことを示すアイコンを表示する
4. The 企画カード shall 背景を既存のカラーパレットの 2 色によるグラデーションとし、配色 (2 色の組み合わせと向き) を企画名から決定的に導く
5. The 企画カード shall 同じ企画名に対して、表示する端末・ページ・サーバー/ブラウザの別によらず常に同じ配色を表示する
6. The 企画カード shall 反対色の組み合わせでもグラデーションの中間が灰色にくすまない色の補間を行う
7. The 企画カード shall カード上の文字を背景に対して WCAG 2.1 AA のコントラスト比 4.5:1 以上、アイコンを 3:1 以上で表示する
8. The 企画カード shall 枠線を持たず、ポインターが重なっている間だけ影を表示する
9. When 利用者が企画カードを選択したとき, the 企画カード shall 該当企画の詳細ページへ遷移する
10. The 企画カード shall 企画一覧ページ以外の画面 (構内マップ等) からも同じ見た目と遷移先で利用できる

### Requirement 4: 企画の場所表示

**Objective:** As a 来場者, I want 企画がどこで行われているかを知りたい, so that 会場で迷わず向かえる

#### Acceptance Criteria

1. Where 企画に CMS のエリア (`map_areas`) が設定されている場合, the 企画一覧ページおよび企画詳細ページ shall エリア名とブース表示名を組み合わせた文字列を場所として表示する
2. Where 企画にステージの出演枠が割り当てられている場合, the 企画一覧ページおよび企画詳細ページ shall 出演するステージ名の文字列を場所として表示する
3. When 企画にエリアと出演枠の双方が設定されているとき, the 企画一覧ページおよび企画詳細ページ shall エリアを優先して場所に表示する
4. When 企画が複数のステージに出演するとき, the 企画一覧ページおよび企画詳細ページ shall 重複を除いたステージ名を連ねて表示する
5. If 企画にエリアはあるがブース表示名がない場合, the 企画一覧ページおよび企画詳細ページ shall エリア名のみを場所として表示する
6. If 企画にエリアも出演枠も設定されていない場合, the 企画一覧ページおよび企画詳細ページ shall 場所の表示を省略する
7. The 企画一覧ページおよび企画詳細ページ shall 場所を CMS のデータから得た文字列としてのみ表示し、地図の表示や `campus-map` の機能には依存しない

### Requirement 5: 企画詳細の表示

**Objective:** As a 来場者, I want 気になった企画の詳しい情報を見たい, so that 行くかどうかを判断できる

#### Acceptance Criteria

1. When 利用者が `/exhibitions/[id]` を開いたとき, the 企画詳細ページ shall 該当企画の企画名・出展団体名・カテゴリ・場所・紹介文・写真を表示する
2. The 企画詳細ページ shall 選択中の写真を大きく表示し、登録された写真の一覧をサムネイルとして並べる
3. When 利用者が写真のサムネイルを選択したとき, the 企画詳細ページ shall 大きく表示する写真をその写真に切り替える
4. If 企画に写真が登録されていない場合, the 企画詳細ページ shall 画像がないことを示す表示を行い、サムネイルの一覧を表示しない
5. The 企画詳細ページ shall 企画一覧ページへ戻る導線を表示する
6. The 企画詳細ページ shall 検索エンジンや SNS で共有されたときに企画名と紹介文が表示されるページ情報 (タイトル・説明・画像) を提供する
7. If 指定された ID の企画が存在しない、または公開状態でない場合, the 企画詳細ページ shall HTTP 404 として「ページが見つからない」表示を返す (不在と非公開は利用者から区別できない扱いとする)
8. If CMS から企画データを取得できない場合, the 企画詳細ページ shall 404 ではなく、取得に失敗したことが分かる表示を行う
9. Where 企画に出演用の企画名 (`stage_name`) が入力されている場合, the 企画詳細ページ shall ステージ出演を示す文脈での企画名にその値を用い、未入力のときは `name` を用いる

### Requirement 6: 団体の SNS・ホームページへのリンク

**Objective:** As a 来場者, I want 出展団体の SNS やホームページへ移動したい, so that 団体の活動をより詳しく知れる

#### Acceptance Criteria

1. Where 企画にリンクが登録されている場合, the 企画詳細ページ shall 登録順にリンクを並べて表示する
2. The 企画詳細ページ shall SNS のリンクを各サービスの公式ロゴ (公式の配色を含む) で、ホームページのリンクをリンクを示すアイコンで表示し、文字ラベルを表示しない
3. The 企画詳細ページ shall 各リンクに、支援技術で読み上げ可能なリンク先のサービス名 (ホームページの場合はその旨) を付与する
4. When 利用者がリンクを選択したとき, the 企画詳細ページ shall 登録された URL を新しいタブで開く
5. If 企画にリンクが 1 件も登録されていない場合, the 企画詳細ページ shall リンク欄を表示しない

### Requirement 7: リンクの登録 (CMS)

**Objective:** As a 出展者, I want 管理画面で SNS やホームページのリンクを簡単に登録したい, so that JSON を手書きせずに正しいリンクを掲載できる

#### Acceptance Criteria

1. The CMS shall 企画のリンクを、サービス種別と URL を 1 組とする行の並びとして、行の追加・削除・並べ替えができる入力欄で登録させる
2. The CMS shall サービス種別の選択肢として X / Instagram / Facebook / YouTube / TikTok / LINE / ホームページ を提供する
3. If `https://` で始まらない URL が入力された場合, the CMS shall 保存を拒否し、入力者に理由を表示する
4. The CMS shall 出展者 (`student_exhibitor`) が自分の企画のリンクを登録・編集できる権限を維持する
5. The CMS shall 管理画面で企画の紹介文 (`description`) 欄を、一覧用の短文ではなく企画の紹介文として入力者に案内する
6. The CMS shall リンクのデータ構造変更を、本番に企画レコードが存在しないうちに適用する (適用前に本番の `student_exhibitions` が 0 件であることを確認する)
7. The CMS shall 出演用の企画名 (`stage_name`、任意、最大 255 文字) を企画に登録できるようにする
8. While 企画のカテゴリに「ステージ」が含まれていない間, the CMS shall 出演用の企画名の入力欄を管理画面に表示しない

### Requirement 8: 企画の共有

**Objective:** As a 来場者, I want 企画のページを友人に共有したい, so that 一緒に回る相手に企画を知らせられる

#### Acceptance Criteria

1. Where 利用者の端末がシステムの共有機能に対応している場合, when 利用者が共有ボタンを選択したとき, the 企画詳細ページ shall 企画名と詳細ページの URL を渡して端末の共有画面を開く
2. Where 利用者の端末がシステムの共有機能に対応していない場合, when 利用者が共有ボタンを選択したとき, the 企画詳細ページ shall 詳細ページの URL をクリップボードへコピーし、コピーしたことを利用者に知らせる
3. If 利用者が共有画面を閉じて共有を取りやめた場合, the 企画詳細ページ shall エラーを表示しない
4. If URL のコピーに失敗した場合, the 企画詳細ページ shall 失敗したことと、URL を手動でコピーできる手段を利用者に示す

### Requirement 9: サイト全体の配色とアイコンの統一

**Objective:** As a 実行委員会, I want サイト全体の配色とアイコンをテーマ「万彩」と明朝体の見出しに調和させたい, so that 一貫した印象の公式サイトにできる

#### Acceptance Criteria

1. The フロントエンド shall サイト全体のページ背景色を暖色寄りの白 (`#fbf8f3`) とする
2. The フロントエンド shall 灰色を用いる表示に暖色寄りのグレーを用いる
3. The フロントエンド shall 背景色を変更した後も、既存ページを含むサイト上の本文テキストが背景に対して WCAG 2.1 AA のコントラスト比 4.5:1 以上を保つ
4. The フロントエンド shall 見出しの色 (`primary`) を現行のまま維持する (Figma のデザインを正とし、見出しは装飾要素としてコントラスト基準の対象外とする)
5. The フロントエンド shall UI アイコンに角の立った細線のアイコンセット (Material Symbols Sharp, weight 300) を用いる
6. The フロントエンド shall SNS のアイコンに各サービスの公式ロゴを公式の配色のまま用い、既存のヘッダー・フッターの SNS アイコンも同じロゴに置き換える
7. The フロントエンド shall 装飾目的のアイコンを支援技術の読み上げ対象から除外する

### Requirement 10: 他機能からの再利用

**Objective:** As a 開発者, I want 企画の URL・カード・データ整形を他の spec から使いたい, so that 構内マップやサイネージで企画表示を重複実装せずに済む

#### Acceptance Criteria

1. The 企画詳細ページ shall 企画 ID だけから組み立てられる安定した URL (`/exhibitions/[id]`) で提供される
2. The フロントエンド shall 企画データを取得し、表示に必要な形 (企画名・出演用の企画名・出展団体名・カテゴリ表示名・場所・サムネイル・リンク) に整形する処理を、企画ページ以外から呼び出せる形で提供する
3. The フロントエンド shall 企画カードの配色を企画名だけから求める処理を、企画カード以外 (サイネージ等) から呼び出せる形で提供する
