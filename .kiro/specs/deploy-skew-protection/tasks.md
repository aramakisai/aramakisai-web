# Implementation Plan

- [x] 1. 旧ビルドの静的アセットを世代として保管・合成する CI スクリプト
- [x] 1.1 (P) 世代の索引の更新と、保管先の取得失敗の判定を作る
  - 新しい世代を索引の先頭に加え、保持世代数を超えた末尾を削除対象として返す。同じコミットを登録し直したときは、重複させずに先頭へ移す
  - 保管先の取得失敗を「キーが存在しない」と「それ以外のエラー」に分ける。前者は wrangler が出す「The specified key does not exist.」で判定する
  - target(prod / dev)ごとに、保管先のキー(世代の tar と索引)を組み立てる。`static-archive/<target>/` の外のキーは扱わない
  - 先頭への追加、切り詰め、再登録、判定の各ケースの単体テストが通る
  - _Requirements: 2.1, 4.1, 4.2, 6.4_
  - _Boundary: StaticArchive_
- [x] 1.2 現ビルドの tar 化・保管・旧世代の合成・索引への登録を、4 つのサブコマンドとして実装する
  - pack: 現ビルドの `_next/static` の中身を tar にまとめる
  - upload: tar を現在のコミットのキーで保管先へ put する
  - restore: 索引を読み、世代の tar を同時 5 本まで並列に取得する。新しい世代から順に、既存のファイルを上書きせずに展開する
    - 索引が無ければ旧世代なしで成功する
    - 索引の取得エラー・不正な索引・tar の取得エラー・展開エラーでは、失敗した操作を出力して失敗する
    - tar が無い世代は warning を出して飛ばす
  - publish: 索引に現在のコミットを登録して put し、保持数を超えた世代の tar を delete する。delete の失敗は warning に留める
  - 各サブコマンドは、扱った世代数とファイル数を標準出力とジョブのサマリに書く。target と保持数の引数が不正なら拒否する
  - 一時ディレクトリでの単体テストが通る(保管先の呼び出しは差し替える)。確かめる内容は、現ビルドと同名の旧ファイルが上書きされないこと、旧世代にだけあるファイルが加わること、索引が無いと成功すること、エラー時に失敗すること
  - _Requirements: 1.1, 1.3, 1.4, 6.1, 6.2, 6.3, 6.4_

- [x] 2. (P) 静的アセットの取得に失敗したタブを、1 回だけ読み込み直す
  - 対象は次の 2 つ。それ以外(画像・地図タイル・外部スクリプト)の失敗では読み込み直さない
    - `/_next/static/` の script・stylesheet の読み込み失敗
    - チャンク読み込みの失敗(`ChunkLoadError`、CSS チャンクの読み込み失敗)の未処理の rejection
  - 読み込み直しは、読み込んでいるビルド(webpack ランタイムの script の URL)ごとに 1 回だけにする。同じビルドで再び失敗しても読み込み直さない。ビルドが変われば、もう一度だけ読み込み直す。ランタイムが見つからなければセッション内で 1 回だけ、sessionStorage が使えなければ読み込み直さない
  - ルートレイアウトの `<head>` 内の、既存の動き設定の初期化スクリプトと同じ位置に、インラインで埋め込む。外部への要求を発生させない
  - jsdom の単体テストが通る。確かめる内容は、対象の失敗で 1 回だけ reload されること、同じビルドでの 2 回目は reload されないこと、ビルドが変われば再び reload されること、画像の失敗では reload されないこと
  - _Requirements: 2.2, 2.3, 5.1_
  - _Boundary: ChunkRecoveryScript, root layout_

- [x] 3. 本番と dev のデプロイジョブに、旧世代の合成と登録を組み込む

  - ワークフローのテストが通る。確かめる内容は次のとおり
    - 並び順: Build < pack < upload < restore < サイトの deploy。publish は最後で、deploy-prod ではリレーより後

    - deploy-preview から static-archive が呼ばれないこと
