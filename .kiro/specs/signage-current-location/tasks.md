# Implementation Plan

- [ ] 1. 地図データをサイネージに届ける土台
- [ ] 1.1 地点の取得と、最大のポリゴンの選択を共有できるようにする
  - 構内マップの地点(`map_points`)の取得と変換を切り出し、一般向けの構内マップとサイネージの両方から使えるようにする。エリアの取得は既存のものを使う
  - エリアの重心を求める処理のうち「最大のポリゴンを選ぶ」部分を単独で使えるようにし、エリア名ラベルとピンが同じポリゴンに乗るようにする
  - 完了時: 一般向けの構内マップの既存テストが変更なしで通り、切り出した処理を呼ぶと従来と同じ地点・同じ重心が得られる
  - _Requirements: 3.2, 4.1_

- [ ] 1.2 サイネージのスナップショットに地図データを加え、構内マップスライドを画像から切り離す
  - スナップショットにエリアと地点を持たせる。エリアの取得に失敗したら地図データ無し、地点だけ失敗したら地点は空にする。どちらの場合もスナップショット全体は失敗にしない
  - 構内マップスライドは画像を持たないようにする
  - 構内マップスライドの巡回は、画像の有無ではなく地図データの有無で決める
  - 地図データの追加で崩れる既存テスト(スナップショットを読む画面・タッチ操作・巡回のテスト)を追随させる
  - 完了時: 構内マップスライドは地図データがあれば 1、無ければ 0 ページになり、画像の有無で変わらない。エリアの取得に失敗しても、スナップショットは地図データ無しで返る。どちらも単体テストで確かめる
  - _Requirements: 1.4, 4.1, 4.6_

- [ ] 2. 共有する部品と CMS
- [ ] 2.1 (P) 現在地ラベルの部品を作る
  - Figma `1555:63` の実測どおり、白の角丸の地に、山吹色の塗りの `location_on`・太字の「現在地」・通常の太さのエリア名を並べる。高さは 46px で、幅はエリア名に合わせて伸びる
  - 配置は呼び出し側に任せ、部品は位置を持たない
  - 完了時: エリア名を渡すと Figma と同じ構成で描画される。部品のテストで、アイコン・「現在地」・エリア名の順と、それぞれの太さを確かめる
  - _Boundary: SignageCurrentLocation_
  - _Requirements: 1.4, 2.1_

- [ ] 2.2 (P) 構内マップの地図に設置エリアのピンを立てる
  - 企画の場所の地図で使っている既存のピンに、色と持ち上げ量を指定する任意の項目を足す。既定値のままなら今の見た目と変わらない
  - 構内マップの地図部品は、設置エリアの ID を任意で受け取る。該当するエリアがあれば、そのエリアの最大のポリゴンの重心にピンを立てる。字形の大きさは 29px、色は山吹色、持ち上げ量は 17px とし、エリアのポリゴン・エリア名ラベル・地点の印より手前に出す
  - 地図を拡大・縮小・移動しても、ピンは設置エリアの位置に留まる。エリアの選択と絞り込みの操作は変わらない
  - 完了時: 部品のテストで次を確かめる。該当する ID ならピンが 1 つ出る。該当しない ID や指定なしなら出ない。既存のピンの呼び出しは出力が変わらない
  - _Boundary: AreaPin, CampusMapView_
  - _Depends: 1.1_
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5_

- [ ] 2.3 (P) CMS で構内マップスライドを画像なしで登録できるようにする
  - 種別「構内マップ」では画像の入力欄を出さず、画像が無くても保存できるようにする。種別「画像」では、画像を必須とする検証を残す
  - フィールドは残し、DB の構造は変えない。既に登録されている構内マップスライドは、保存し直さなくてもそのまま使える
  - 構内マップに画像を求めている既存の 2 つのテストを、画像なしで通る内容に書き換える
  - 完了時: CMS のテストで次を確かめる。構内マップは画像なしで検証を通る。画像スライドは画像なしで失敗する
  - _Boundary: signage-slides.ts_
  - _Requirements: 5.1, 5.2, 5.3, 5.4_

- [ ] 3. 設置エリアの受け渡しと各画面への組み込み
- [ ] 3.1 URL の設置エリアを受け取り、サイネージ全体に渡す
  - `/signage` は検索パラメータ `map_area` を文字列のまま受け取り、サイネージ本体に渡す
  - サイネージ本体は、スナップショットのエリアから ID が文字列で一致するものを探して設置エリアとし、メインの表示・縦型ヘッダー・タッチ操作に渡す。一致しなければ設置エリア無しとする
  - パラメータの有無で、ラベルとピン以外の表示と巡回を変えない
  - 完了時: 画面のテストで次を確かめる。実在の ID で設置エリアが決まる。パラメータ無し・`abc`・存在しない ID では設置エリア無しになる
  - _Requirements: 1.1, 1.2, 1.3, 1.6_

- [ ] 3.2 (P) 横型のスライドの右上に現在地ラベルを重ねる
  - スライドごとに、スライド枠の右から 24px の位置へラベルを重ね、スライドと一緒に切り替える。上端は、見出しチップの無い種別(登録画像・レイアウト)なら 24px、チップのある種別(構内マップ・協賛・落とし物・駐車場・タイムテーブル)なら 27px にする
  - 縦型のメイン枠(横型を縮小した表示)ではラベルを描かない
  - スライドの描画に設置エリアの ID を渡す口を足す(構内マップスライドのピンで使う)。緊急地震速報の表示からは渡さないので、速報ではラベルもピンも出ない
  - 完了時: 画面のテストで次を確かめる。全種別のスライドにラベルが出て、上端が種別ごとに 24 または 27px になる。縦型と速報では出ない
  - _Boundary: SignageMain_
  - _Depends: 2.1, 3.1_
  - _Requirements: 2.2, 2.3, 2.7_

- [ ] 3.3 (P) 縦型ヘッダーの開催日の左に現在地ラベルを置く
  - 開催日の行を横並びにし、ラベル → 開催日の順に 43px 空けて並べ、上下中央をそろえる。エリア名が長くても、ラベルは開催日の左に付いたまま伸び、開催日と重ならない
  - 完了時: 画面のテストで次を確かめる。設置エリアがあればラベルが開催日より前に並ぶ。無ければ出ない
  - _Boundary: SignagePortraitHeader_
  - _Depends: 2.1, 3.1_
  - _Requirements: 2.4_

- [ ] 3.4 (P) タッチ操作の全画面にラベルを出し、構内マップへ設置エリアを渡す
  - タッチ操作の左下(左から 24px、上から 981px)に、ほかの要素より前面へラベルを置く。ラベルはタップを素通りさせ、下の項目の操作を妨げない
  - 地図の行き先で設置エリアがあれば、行き先のパスに `?map_area=<ID>` を付ける。最初の表示と行き先の切替の両方で付け、ほかの行き先には付けない
  - タッチ操作の構内マップは、開いたときに URL の `map_area` を読んでエリアと照合し、地図にピンを立てる
  - 完了時: 画面のテストで次を確かめる。すべての行き先でラベルが出る。地図の行き先の iframe の URL にだけ `map_area` が付く。タッチ操作の構内マップでピンが立つ
  - _Boundary: SignageTouchLayer, TouchMap_
  - _Depends: 2.1, 2.2, 3.1_
  - _Requirements: 1.5, 2.5, 2.6, 3.1, 3.4_

- [ ] 3.5 構内マップスライドを地図にする
  - 構内マップスライドを、タッチ操作の構内マップと同じ地図(タイル・ポリゴン・エリア名ラベル・施設の印)を描く専用のスライドに替える。範囲は全エリアが収まるように取り、外れ値のエリアは除く
  - 地図は操作を受けない層(`inert`)に描き、来場者が拡大・縮小・移動できないようにする
  - 見出しチップ「構内マップ」を左上に、OpenStreetMap の著作権表示を右下に、タッチ操作の構内マップと同じ書式で出す。設置エリアがあればピンを立てる
  - 画像スライドから構内マップ用の分岐を外し、画像スライド専用にする
  - 縦型では、ほかのスライドと同じく横型の表示を縮小して出す
  - 完了時: 部品のテストで次を確かめる。構内マップスライドが画像を使わずに地図を描き、地図の層が `inert` になっている。見出しチップが出て、設置エリアのピンが渡される
  - _Depends: 1.2, 2.2, 3.2_
  - _Requirements: 3.1, 4.1, 4.2, 4.3, 4.4, 4.5_

- [ ] 4. 実ブラウザでの確認(Playwright の headless、ローカルの `make dev` と共有 CMS)
- [ ] 4.1 現在地ラベルの位置と寸法を測る
  - ローカル CMS にある実在のエリア「2号館」と「武道館ステージ」の ID で、`/signage?map_area=<ID>` を 1920×1080 と 1080×1920 で開く
  - 横型: スライド枠の右から 24px、上から 24 または 27px、高さ 46px
  - 縦型: 開催日の左 43px、開催日と上下中央がそろう。「武道館ステージ」でも開催日と重ならない
  - タッチ操作: 左上の座標が 24,981
  - パラメータ無しと `?map_area=99999` では、ラベルもピンも出ない
  - 完了時: 各値の実測結果と、各画面のスクリーンショットのパスがそろい、Figma のフレームと並べて目視で比べてある
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 2.1, 2.2, 2.3, 2.4, 2.5, 2.6_

- [ ] 4.2 ピンと地図の振る舞いを測る
  - 構内マップスライドとタッチ操作の構内マップで、次を画素で測る。エリア名ラベルの高さ(22px)、ピンの描画幅と高さ(約 19×24px)、ピンの先端とラベル上端の距離(6px)。ラベルが 22px でなければ、比率から値を求め直す
  - 構内マップスライドで、ポリゴンやラベルからドラッグ・ピンチしても地図が動かないことを、横型・縦型の両方で確かめる
  - タッチ操作の構内マップで、ラベルの下にある左パネルの項目をタップでき、拡大・縮小・移動してもピンが設置エリアに留まることを確かめる
  - 構内マップスライドの著作権表示の位置を、Figma(枠の右から 26px、下端 0)と比べる
  - 完了時: 各値の実測結果と、スクリーンショットのパスがそろっている
  - _Requirements: 3.2, 3.3, 3.4, 3.5, 4.1, 4.2, 4.3, 4.4, 4.5_
